# 간편 HTTPS 첫 전송: 인증서 자동 준비

Arduino UNO R3 + SIM7080G 전용 독립 예제입니다. APN·장치 UID·장치키만 설정하고
이 스케치를 업로드합니다. 추가 센서, Python, 인증서 설치용 브리지 스케치가 필요하지 않습니다.
기존 예제 01~06과 서버 설정을 바꾸지 않습니다.

## 준비와 실행

1. 전원을 끈 상태에서 쉴드·LTE 안테나·USIM을 연결하고 제품 규격에 맞게 전원을 공급합니다.
   UNO 3.3V 핀으로 모뎀을 구동하지 않습니다. UNO R4/ESP32용이 아닙니다.
2. https://shield.serial.kr/devices 에서 본인 제품의 일회용 등록 코드로 장치를 등록합니다.
   발급받은 장치 UID·장치키를 준비합니다. 로그인 비밀번호·ICCID·등록 코드와 장치키는 다릅니다.
3. ZIP을 풀고 `07_easy_https/07_easy_https.ino`를 엽니다. `src` 폴더를 그대로 둡니다.
4. `config.example.h`를 같은 폴더의 `config.h`로 복사하여 `YOUR_*` 세 값을 바꿉니다.
   1NCE SIM의 APN은 `iot.1nce.net`입니다. 다른 사업자는 해당 APN을 확인합니다.
   UID는 영문·숫자·점·밑줄·하이픈, 최대 64자; 장치키는 소문자 16진수 64자입니다.
5. Arduino IDE에서 Arduino AVR Boards → Arduino Uno, 연결된 COM 포트를 선택하여 업로드합니다.
   SoftwareSerial은 보드 코어에 포함되어 있습니다. 시리얼 모니터는 115200 baud입니다.
6. `[CA]` → `[READY]` → `[HTTPS] 200`을 확인합니다. 인증서 초기 저장 중에는 전원을 끄지 마세요.
   https://shield.serial.kr/devices 에서 마지막 수신 시각과 LTE 상태를 확인합니다.

설정이 비어 있으면 컴파일은 되지만 `[CONFIG]` 안내 후 멈춥니다. `config.h`는 공유하지 마세요.
펌웨어에는 계정 비밀번호, 결제 키, Firebase 키가 필요하지 않습니다.

## 전송하는 데이터

실제 모뎀의 CSQ(신호)와 망 등록 상태, UNO 가동 시간만 HTTPS로 보냅니다.
`shield_v=2`, `device_uid`, `build_tag=example-https-7`, `ts`, `csq`, `reg`,
`diag.gnss=0`, `points=[]` 형식입니다. 임의 TEXT, 온습도, GPS 좌표를 만들지 않습니다.
지도·센서 그래프가 비어 있어도 정상입니다. 기본 주기는 60초 대기 + 망/NTP/HTTPS 처리 시간입니다.
실패한 표본을 저장하거나 즉시 재전송하지 않습니다. 전원 중단·망 장애 시 무손실을 보장하는 예제가 아닙니다.

## 자동 인증서 준비 방식

- `src/ShieldRootCA.h`의 **공개 ISRG Root X1**을 UNO의 플래시에 저장합니다. 장치 비밀키가 아닙니다.
  인증서 전체를 2 KiB SRAM에 복사하지 않고 한 바이트씩 모뎀으로 보냅니다.
- 새 예제 전용 `sh07-x1-22b557a2.pem` 파일만 사용합니다. 기존 `shield-ca.pem`,
  `shield-example-ca.pem`, Firebase 인증서에는 쓰지 않습니다.
- 부팅 시 모뎀의 파일 크기와 PEM 내용을 읽어 포함된 인증서와 비교합니다. 다르거나 없으면
  전용 파일만 다시 저장하고 읽어서 확인합니다. 일치하는 PEM은 다시 쓰지 않습니다.
- 변환 중 전원이 끊긴 경우를 복구하기 위해 모뎀 내부 인증서 형식 변환은 부팅마다 확인합니다.
  60초마다 전송할 때 인증서를 저장·변환하지 않습니다.
- SIM7080G가 TLS 1.2를 처리합니다. SNI=`shield.serial.kr`, CA 지정, 날짜 검사 사용,
  NTP 시각 동기화를 유지합니다. HTTP 대체 전송이나 인증서 검사 생략 옵션은 없습니다.
- 목적지는 `https://shield.serial.kr/ingest/shield`로 고정되어 있습니다. 다른 도메인을 쓰려면
  해당 서버의 인증서 신뢰 관계까지 검토해야 하므로 이 입문 예제에서는 설정 항목으로 노출하지 않습니다.
- 2026-10-06 PC에서 현재 Shield 서버의 TLS 1.2 체인·호스트명을 검증했습니다.
  서버 신뢰 루트가 바뀌면 검토된 새 패키지가 필요합니다. 일반적인 서버 인증서 갱신마다
  같은 신뢰 루트를 다시 설치할 필요는 없습니다.

공식 CA 원본: https://letsencrypt.org/certs/isrgrootx1.pem

## 오류 읽기

| 표시 | 확인할 것 |
|---|---|
| `[CONFIG]` | config.h의 APN·UID·64자 장치키, placeholder 잔존 |
| `[MODEM]` | 전원·쉴드 핀·UART·모뎀 재부팅 |
| `[CA] ... failed` | 모뎀 파일 저장/읽기/변환 실패, 전원·모뎀 펌웨어 호환성 |
| `[SIM]` | USIM 삽입·PIN·개통 상태 |
| `[NET]` | APN·안테나·망 등록·잔량 |
| `[TIME]` | NTP 접근과 올바른 시각 확보. 날짜 검사를 끄지 마세요. |
| `[TLS CONFIG]` | 모뎀에서 TLS 설정 명령을 거절함 |
| `[TLS CONNECT]` | 연결 실패 단계. 원인은 네트워크·CA·시각·서버 중 추가 확인 필요 |
| `[SEND]` | 요청 접수 여부가 확인되지 않음. 즉시 중복 전송하지 않음 |
| `[HTTPS] 200` | 서버 접수. 내 장치에서 마지막 수신 확인 |
| `[HTTPS] 400` | 페이로드 형식 확인 |
| `[HTTPS] 401 / 403` | UID·장치키 확인 |
| `[HTTPS] 409` | Shield 내 장치에서 먼저 계정에 등록 |
| `[HTTPS] 429 / 5xx` | 전송 빈도 또는 서버 상태 확인 |
| `[CLOSE]` / `[STOP]` | 응답 지연으로 명령/데이터 경계가 불명확하거나 초기화 실패. 원인 확인 후 UNO 리셋 |

오류 표시는 실패한 단계를 나타내며, 모뎀의 일반 ERROR만으로 인증서 만료 등 세부 원인을 단정하지 않습니다.
장치키나 요청 전문을 디버그 로그로 출력하지 않습니다.

## 검증 범위

UNO 컴파일, 모뎀 응답 시뮬레이션(인증서 누락·변조·변환 실패·시간 오류·TLS 실패 시 키 전송 차단 등),
격리 서버의 실제 페이로드 규격을 검사합니다. PC TLS 검증은 실제 모뎀의 서버 이름 검증을 대신하지 않습니다.
**이 교육용 스케치의 실제 모뎀 인증서 자동 설치·LTE HTTPS 전송은 실물 검증 전입니다.**
실물에는 자동 업로드하지 않았습니다. 이 예제로 GPS/KC·결제·USIM 충전 API를 호출하지 않습니다.

참고: SIMCom HTTP(S) Application Note V1.02, SSL Application Note V1.00,
SIM7070/SIM7080/SIM7090 AT Command Manual V1.03의 CFS 파일 명령.
