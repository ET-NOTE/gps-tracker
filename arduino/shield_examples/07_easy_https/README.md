# 1NCE 간편 HTTPS 첫 전송: 업로드 후 바로 등록

1NCE 설정과 인증서가 포함되어 있습니다. 코드를 수정하지 않고 업로드한 뒤, 시리얼 모니터의 등록 코드로 내 장치에 연결하세요.

## 1NCE 쉴드와 계정 준비

전원을 끄고 UNO R3에 SIM7080G 쉴드·LTE 안테나·개통된 1NCE USIM을 연결합니다. 제품 규격에 맞는 전원을 사용하세요. 이 예제는 추가 센서가 필요하지 않습니다.
Shield 계정으로 로그인해 두세요. 기존 초대코드 회원가입 정책은 그대로이며, 로그인한 사용자의 장치 등록에는 관리자 작업이 필요하지 않습니다.
! 1NCE APN iot.1nce.net과 서버 주소는 예제에 포함되어 있습니다. SHIELD_UID·SHIELD_DEVICE_UID·SHIELD_DEMO_UID 중 어느 것도 입력하지 않습니다. 장치 UID와 키는 최초 HTTPS 연결 때 자동으로 받아 보드에 저장합니다.
(이미지) 실제 UNO와 쉴드·LTE 안테나·1NCE USIM 연결 모습.
! UNO 컴파일·서버 연동·모뎀 응답 시뮬레이션 검증을 거친 예제이며, 이 버전의 실물 LTE 전송은 확인 전입니다.

## 전체 ZIP 그대로 업로드

아래의 v2 전체 ZIP을 내려받아 새 폴더에 압축을 풀고 07_easy_https/07_easy_https.ino를 엽니다. src 폴더를 함께 유지하세요. 예전 ZIP 폴더 위에 덮어쓰지 마세요.
[Arduino 설치](/examples/arduino-basics-install), [포트 확인](/examples/arduino-basics-com-port), [업로드 방법](/examples/arduino-basics-upload)을 참고하세요. 보드는 Arduino AVR Boards → Arduino Uno입니다.
config.h 생성, UID·키 복사, Python이나 인증서용 브리지 스케치 업로드 없이 그대로 컴파일하고 업로드합니다. SoftwareSerial과 EEPROM은 UNO 보드 코어에 포함되어 있습니다.
시리얼 모니터를 115200 baud로 엽니다. 처음에 [07 v2] 1NCE auto setup 문구가 표시되는지 확인하세요.
(이미지) Arduino IDE에서 UNO와 포트를 선택한 업로드 화면.

## 시리얼 등록 코드를 내 장치에 입력

시리얼에서 [CA] → [READY] → [REGISTER] abcd-1234-ef56-7890 형태의 출력을 기다립니다. 코드는 장치마다 다릅니다. 여기에 적힌 예시 코드를 사용하지 마세요.
쉴드는 인증서를 자동 준비한 뒤 HTTPS로 개별 UID·키·등록 코드를 발급받습니다. UID와 키는 자동 저장되며 시리얼에는 등록 코드만 보여줍니다. 첫 인증서 저장 중 전원을 끄지 마세요.
[내 장치](/devices) → 장치 등록에서 시리얼에 나온 등록 코드와 원하는 장치 이름을 입력합니다. 등록 코드는 24시간 동안 한 번 사용할 수 있습니다. 관리자에게 UID·키를 요청할 필요가 없습니다.
! 웹 등록 전 [HTTPS] 409는 등록을 기다리는 정상 상태입니다. 웹에서 등록한 뒤 다음 전송부터 200으로 바뀝니다.
(이미지) 시리얼의 [REGISTER] 출력과 내 장치 등록 창. 등록 코드는 가려주세요.

## 내 장치에서 수신 확인

[HTTPS] 200은 서버가 실제 LTE 상태를 접수했다는 뜻입니다. [내 장치](/devices)에서 등록한 이름을 선택하고 마지막 수신 시각과 LTE 상태를 확인합니다.
이 예제는 CSQ·망 등록 상태·UNO 가동 시간만 전송합니다. 온습도·GPS 좌표는 보내지 않으므로 센서 카드와 지도에 값이 없어도 정상입니다.
전송 간격은 기본 60초 대기와 망/NTP/HTTPS 처리 시간을 합친 시간입니다. 등록 직후 첫 수신까지 이 시간을 기다려 주세요.
(이미지) 실물의 [HTTPS] 200과 내 장치의 마지막 수신 화면.

## 재시작과 문제 해결

같은 보드를 재부팅하거나 같은 예제를 다시 업로드해도 EEPROM에 저장한 연결 정보를 재사용합니다. 등록 코드를 다시 입력할 필요가 없습니다.
아직 등록하지 않은 코드가 24시간을 넘겼다면 시리얼 모니터에서 줄 끝을 새 줄로 설정하고 NEW를 입력해 전송하세요. 다음 대기 구간에서 새 장치 연결 정보를 발급받아 [REGISTER]를 표시합니다.
! NEW는 이 예제의 보드 식별 정보를 초기화합니다. 이미 등록한 장치에는 사용하지 마세요. 기존 서버 장치·수신 기록은 남고 새 장치로 등록됩니다. 다른 사람에게 보드를 넘기기 전에도 기존 계정 연결과 EEPROM을 확인하세요.
[SIM]은 유심 인식, [NET]은 1NCE 개통·안테나·잔량, [TIME]은 NTP 시각, [CA]는 인증서 저장, [TLS CONNECT]는 HTTPS 연결을 확인합니다. [STOP]은 원인을 해결한 뒤 UNO를 리셋합니다. 401/403은 만료 또는 저장한 연결 정보 문제이며, 키를 직접 입력하지 말고 ZIP의 복구 안내를 확인하세요.
[SIM7080G 첫 연결](/examples/shield-uno-connect), [DHT11 측정](/examples/shield-uno-dht11), [DHT11 HTTPS 전송](/examples/shield-uno-upload)으로 확장할 수 있습니다.
! 자동 등록은 이 07 v2 예제의 기능입니다. 기존 04·06 HTTPS 예제와 08 HTTP 학습 예제는 각자의 준비 절차를 사용합니다.

## 전송하는 데이터

실제 모뎀의 CSQ(신호)와 망 등록 상태, UNO 가동 시간만 HTTPS로 보냅니다.
`shield_v=2`, `device_uid`, `build_tag=example-https-7`, `ts`, `csq`, `reg`,
`diag.gnss=0`, `points=[]` 형식입니다. 임의 TEXT, 온습도, GPS 좌표를 만들지 않습니다.
지도·센서 그래프가 비어 있어도 정상입니다. 기본 주기는 60초 대기 + 망/NTP/HTTPS 처리 시간입니다.
실패한 표본을 저장하거나 즉시 재전송하지 않습니다. 전원 중단·망 장애 시 무손실을 보장하는 예제가 아닙니다.

## 자동 인증서 준비 방식

- `src/ShieldRootCA.h`의 **공개 ISRG Root X1**을 UNO의 플래시에 저장합니다. 장치 비밀키가 아닙니다.
  인증서 전체를 2 KiB SRAM에 복사하지 않고 한 바이트씩 모뎀으로 보냅니다.
- 새 예제 전용 `sh07-x1-22b557a2.pem` 파일만 사용합니다. 기존 `shield-ca.pem`,
  `shield-example-ca.pem`, Firebase 인증서에는 쓰지 않습니다.
- 부팅 시 모뎀의 파일 크기와 PEM 내용을 읽어 포함된 인증서와 비교합니다. 다르거나 없으면
  전용 파일만 다시 저장하고 읽어서 확인합니다. 일치하는 PEM은 다시 쓰지 않습니다.
- 변환 중 전원이 끊긴 경우를 복구하기 위해 모뎀 내부 인증서 형식 변환은 부팅마다 확인합니다.
  60초마다 전송할 때 인증서를 저장·변환하지 않습니다.
- SIM7080G가 TLS 1.2를 처리합니다. SNI=`shield.serial.kr`, CA 지정, 날짜 검사 사용,
  NTP 시각 동기화를 유지합니다. HTTP 대체 전송이나 인증서 검사 생략 옵션은 없습니다.
- 목적지는 `https://shield.serial.kr/ingest/shield`로 고정되어 있습니다. 다른 도메인을 쓰려면
  해당 서버의 인증서 신뢰 관계까지 검토해야 하므로 이 입문 예제에서는 설정 항목으로 노출하지 않습니다.
- 2026-10-06 PC에서 현재 Shield 서버의 TLS 1.2 체인·호스트명을 검증했습니다.
  서버 신뢰 루트가 바뀌면 검토된 새 패키지가 필요합니다. 일반적인 서버 인증서 갱신마다
  같은 신뢰 루트를 다시 설치할 필요는 없습니다.

공식 CA 원본: https://letsencrypt.org/certs/isrgrootx1.pem

PEM SHA-256: `22b557a27055b33606b6559f37703928d3e4ad79f110b407d04986e1843543d1`

## 오류 읽기

| 표시 | 확인할 것 |
|---|---|
| `[07 v2]` | 새 자동 등록 예제의 시작 표시 |
| `[MODEM]` | 전원·쉴드 핀·UART·모뎀 재부팅 |
| `[CA] ... failed` | 모뎀 파일 저장/읽기/변환 실패, 전원·모뎀 펌웨어 호환성 |
| `[SIM]` | USIM 삽입·PIN·개통 상태 |
| `[NET]` | APN·안테나·망 등록·잔량 |
| `[TIME]` | NTP 접근과 올바른 시각 확보. 날짜 검사를 끄지 마세요. |
| `[TLS CONFIG]` | 모뎀에서 TLS 설정 명령을 거절함 |
| `[TLS CONNECT]` | 연결 실패 단계. 원인은 네트워크·CA·시각·서버 중 추가 확인 필요 |
| `[SEND]` | 요청 접수 여부가 확인되지 않음. 즉시 중복 전송하지 않음 |
| `[HTTPS] 200` | 서버 접수. 내 장치에서 마지막 수신 확인 |
| `[HTTPS] 400` | 페이로드 형식 확인 |
| `[HTTPS] 401 / 403` | 미등록 코드의 만료 또는 저장 정보 문제. 미등록 장치는 NEW로 새 코드를 발급; 이미 등록한 장치는 먼저 내 장치 목록 확인 |
| `[HTTPS] 409` | Shield 내 장치에서 먼저 계정에 등록 |
| `[HTTPS] 429 / 5xx` | 전송 빈도 또는 서버 상태 확인 |
| `[CLOSE]` / `[STOP]` | 응답 지연으로 명령/데이터 경계가 불명확하거나 초기화 실패. 원인 확인 후 UNO 리셋 |

오류 표시는 실패한 단계를 나타내며, 모뎀의 일반 ERROR만으로 인증서 만료 등 세부 원인을 단정하지 않습니다.
장치키나 요청 전문을 디버그 로그로 출력하지 않습니다.

## 검증 범위

UNO 컴파일, 모뎀 응답 시뮬레이션(인증서 누락·변조·변환 실패·시간 오류·TLS 실패 시 키 전송 차단 등),
격리 서버의 실제 페이로드 규격을 검사합니다. PC TLS 검증은 실제 모뎀의 서버 이름 검증을 대신하지 않습니다.
**이 교육용 스케치의 실제 모뎀 인증서 자동 설치·LTE HTTPS 전송은 실물 검증 전입니다.**
실물에는 자동 업로드하지 않았습니다. 이 예제로 GPS/KC·결제·USIM 충전 API를 호출하지 않습니다.

참고: SIMCom HTTP(S) Application Note V1.02, SSL Application Note V1.00,
SIM7070/SIM7080/SIM7090 AT Command Manual V1.03의 CFS 파일 명령.

## 연결 정보와 제한

- HTTPS `/device/bootstrap`에서 개별 UID·키·일회용 코드를 발급받습니다. 공용 비밀키를 펌웨어에 넣지 않습니다. 서버는 키와 코드의 해시만 보관합니다.
- 등록 전에는 수신 데이터가 저장되지 않습니다. 본인 계정 로그인 후 등록 코드를 제출해야 연결됩니다.
- UNO EEPROM 768~896 바이트를 사용합니다. 체크섬과 마지막 유효 표시로 중간 저장을 감지합니다. 키는 EEPROM에서 암호화되지 않으므로 등록된 보드·EEPROM 덤프를 공유하지 마세요.
- 새로운 보드/EEPROM 초기화는 새로운 장치입니다. 기존 실물 장치의 서버 계정 연결을 자동 인수하지 않습니다.
- 서버는 발급 속도·대기 장치 수·계정별 등록 수를 제한합니다. 429는 기다렸다가 다시 시도하세요.
- 1NCE 이외의 USIM은 이 무설정 예제의 대상이 아닙니다.
