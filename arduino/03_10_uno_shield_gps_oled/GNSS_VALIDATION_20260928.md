# 2026-09-28 SIM7080G 연속 측위 / LTE 분리 진단

대상은 COM26의 UNO R3 쉴드이며 `03_10`만 수정했다. 별도 L80 모듈이 아닌 SIM7080G의 `CGNSPWR` / `CGNSINF`를 사용한다. KC 펌웨어 및 운영 서버 바이너리·설정은 이 변경에서 수정하지 않았다.

## 확인된 코드 문제와 수정

- 위치가 없어도 60초마다 HTTP 때문에 GNSS가 중단됨 → 최소 전송 간격은 60초로 유지하되, 유효 위치가 없으면 최대 600초 연속 측위를 허용한다. 만료 후에는 상태를 전송하여 무한 대기에 빠지지 않는다.
- GNSS 동작 중 LTE 등록 조회 실패가 측위를 중단시킬 수 있음 → 등록 조회/복구는 GNSS off 구간으로 옮긴다. HTTP 실패 중에도 GNSS는 off로 유지하고 통신부터 복구한다.
- 빈 fix 상태와 실제 품질 필터 거절을 구분할 수 없음 → `reason`, `raw_fix`, `window_s`, `diag.gnss` 진단을 추가했다.
- 긴 좌표의 잘림, 비정상 위성 수의 정수 overflow, 빈 응답 뒤 오래된 UTC의 재사용을 방어한다.
- 명시적인 `i` 키로 LTE RF를 끈 GNSS 단독 비교 시험을 최대 180초 수행한다. 성공·실패·시간 초과·재부팅 후에도 RF 복구를 재시도한다. 정상 주기에 자동 RF 재설정을 추가하지 않았다.

## v8 연속 측위 실기

2026-09-28 10:48:55 KST 서버 수신 후 10:58:54까지 GNSS 가동을 유지했다. 5초마다 CGNSINF를 조회했고, `window_s=600`까지 중간 HTTP 전송/망 재등록/모뎀 재부팅 없이 진행했다. 관찰된 응답은 `NO_FIX_STATUS`, `raw_fix=-1`, `SV=-1`, HDOP=0.1이었다. 값이 비어 있다는 뜻이며 음수 위성을 관측한 것이 아니다. 유효 FIX는 0회다.

600초 후 HTTP 200, 10:58:59 KST 서버 저장, 다음 측위 창 시작까지 확인했다. 수신 간격은 약 604초로 의도한 상한 동작과 일치한다. 이 결과만으로 안테나 고장이라고 확정할 수 없다.

## LTE RF 중지 비교 시험

11:00:01 KST에 수동 `i`를 한 번 실행했다. 조회 응답에서 `CFUN: 0`, `CGNSPWR: 1`을 확인했다. 시작 직후 CGNSINF run=0이 잠시 관찰됐고, 5초 이후 run=1 / fix 상태 없음으로 바뀌었다.

11:02:58 KST, LTE RF 중지 후 약 175초 지점에 처음으로 위성 4개 / HDOP 13.9가 나타났다. 11:03:03까지 180초 시험에서 유효 FIX는 0회였다. 이후 자동으로 LTE를 복구하여 11:03:10 로밍 등록, 11:03:15 HTTP 200, 서버 시각 11:03:17 저장을 확인했다. `diag.gnss=3`도 운영 DB에 저장됐다. 시작 직후 잠깐 run=0이었던 응답을 제외하면 GNSS 조회는 계속 정상 응답했으며 모뎀 재부팅은 관찰되지 않았다.

정상 모드 복귀 후 UTC·좌표 필드와 위성 2~4개가 관찰되었다. 모뎀 fix 상태는 여전히 비어 있고 HDOP 최선값도 13.7이어서 이 좌표는 유효 위치로 전송하지 않았다. 사용자는 이 시간대에 장치나 안테나의 위치·연결을 변경하지 않았다고 확인했다. 연속 측위 시간/무선 상태 전환과 관련이 있을 가능성은 있지만 어느 조치의 효과인지는 분리되지 않았다.

위성 수신 시작이라는 새 관찰에 따라 11:05:51~11:08:52 KST에 180초 RF 중지 시험을 한 차례 더 수행했다. 이 구간에는 위성 2~3개, HDOP 4.0~500.0이 관찰됐고 모뎀의 fix 상태는 계속 비어 있었다. 유효 FIX는 여전히 0회다. 두 번째 종료 후에도 11:09:00 로밍 등록, 11:09:05 HTTP 200, 서버 시각 11:09:07 저장으로 자동 복구를 확인했다. v9 전체 관찰에서 최종 HTTP 실패나 RDY 재부팅은 없었다. 이미 해제된 SHDISC/PDP 정리 명령의 오류는 기존처럼 최종 HTTP 결과와 구분한다.

연속 가동 및 LTE RF 중지 조건에서도 유효 측위는 아직 확인되지 않았으므로, 60초 전송 주기나 펌웨어 품질 필터만으로 미수신을 설명할 수 없다. 위성 신호를 일부 받기 시작한 사실과 유효 위치를 얻은 사실을 구분해야 한다. 현재 원인을 안테나/전원/환경 중 하나로 확정할 수는 없다.

## 다음 물리 확인

별도 GPS 수신 모듈이 없어도 SIM7080G의 GNSS 안테나와 해당 RF 회로는 필요하다. 현재 안테나 종류·연결 상태·하늘 개방 여부는 원격에서 확인되지 않았다. GNSS 안테나 단자 연결, 수신 환경, 능동 안테나 바이어스 또는 수동 안테나 LNA 전원을 순서대로 확인해야 한다. 알려지지 않은 보드 GPIO를 임의로 구동하지 않았다.

현재 업로드된 v9는 정상 자동 운영으로 복귀한 상태다. 유효 위치가 없으면 최대 10분마다 상태를 보고한다. 측위에 성공하면 최소 60초 간격 보고로 돌아간다. 공개 수신 페이지의 위성 수는 기존 페이로드 정책상 유효 위치 전송 때만 표시되므로, 미측위 중의 위성 수 변화는 시리얼 상세 로그로 확인한다.
