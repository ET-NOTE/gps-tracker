## 동작 변경

- 일반 빌드는 수동 RF 차단/재등록·DTR 변경 키, 5초 단위 상세 좌표 로그, 시작 시 모뎀 버전/위성 모드·CCID 조회, 연결 실패 후 DNS 상세 진단을 포함하지 않는다. 오류와 전송 결과, GNSS 코드·위성 수·PV 요약은 유지한다.
- 유효 위치는 60초 대기 후 전송한다. 최초/장시간 미측위에는 최대 600초를 주며, 직전 성공 보고에 위치가 있으면 다음 측위 구간에서 최대 120초를 기다린다. 그 구간에서도 위치를 못 얻으면 상태를 전송한 뒤 다음 구간을 600초로 돌린다. 서버 연결 중 만료되어 제외된 위치는 짧은 구간을 시작하는 근거로 쓰지 않는다.
- 정상 HTTP 세션 종료를 기억하여 다음 전송 직전의 중복 `SHDISC`를 생략한다. 처음 또는 결과가 불명확할 때만 `SHSTATE?`로 상태를 확인한다. 종료 확인 실패 시 GNSS 재가동을 보류하고 기존 통신 재시도 경로로 복구한다.
- 진단 빌드의 DNS 상세 확인은 연속 실패 첫 시도에 한정한다. 수동 `n` 시험도 `i`와 같이 RF 복구가 확인될 때까지 복구 대기를 유지한다.
- 검증된 PWRKEY/DTR 기본값, GNSS off → HTTP → GNSS on 순서, UTC/좌표/HDOP/위성 수 검증, 늦은 응답 격리 및 SHBOD 프롬프트 처리는 유지한다.

## 회귀 시험

`etcom-hub`에서 실제 스케치를 C++17 호스트 스텁과 함께 일반/진단 두 가지로 컴파일하여 ASan·UBSan, `-Wall -Wextra -Werror` 시험을 통과했다. 정상/미측위 JSON은 각 빌드에서 JSON 파서로 확인했고 256-byte 버퍼 내에 들어갔다.

확인한 주요 경계:

- 초기 600초, 위치 전송 후 120초, 지속 미수신 시 600초 복귀, 위치 재확보 시 60초 보고, 타이머 wraparound.
- HTTP 구성/헤더/요청 실패, 503, 지연된 본문 프롬프트, GNSS 재가동 실패, 자동 재시도.
- UNO만 재시작되어 모뎀 HTTP가 열린 상태, 연결/종료 명령은 적용됐지만 응답이 유실된 상태, 종료 실패 시 GNSS 보류, 다음 시도 복구.
- 일반 빌드에서 수동 키·RF/DNS 진단 미실행, 진단 빌드의 RF 복구 실패/재부팅/시간 초과 처리.
- 잘린 좌표, NaN 등 잘못된 숫자, 위성 수 overflow, 빈 응답 뒤 오래된 UTC 재사용, 전송 직전 오래된 위치 제외.

호스트 시험은 실제 전파 환경, 전원, UART 시간 특성을 재현하지 않는다. 120/600초 정책의 경계와 장애 주입은 호스트에서 검증했으며, 실기에서는 정상 연속 위치 전송을 검증했다.
