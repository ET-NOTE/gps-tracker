# Shield 공통 폭·반응형 보정

## 확인한 문제와 변경

- FAQ/계정/포인트 1,000px, 가이드 1,150px, 일반 본문 1,200px,
  헤더·장치 1,440px로 나뉜 최대 폭을 `--page-max-width: 1280px`로 통합했다.
  헤더/본문/홈 hero/푸터가 같은 기준을 사용한다. 로그인 폼·읽기 전용 글의
  내부 가독성 제한은 유지한다.
- `--page-gutter`를 데스크톱 32px, 태블릿 24px, 모바일 16px로 공유한다.
  스크롤바 유무에 따른 화면 전환 시 좌우 이동은 `scrollbar-gutter: stable`로 줄인다.
- 예제 상단 장식 이미지를 별도 예약 영역에 두어 이미지 크기가 제목·breadcrumb의
  세로 위치를 바꾸지 않도록 했다. 모바일에서는 이미지 영역 자체를 없앤다.
- FAQ 검색창은 독립 grid 열로 배치하고 좁은 화면에서 제목 아래로 이동한다.
  기본 input 스타일의 specificity를 낮춰 검색창 이중 테두리와 padding 충돌을 제거했다.
  키보드 검색 초점은 외곽 focus-within으로 표시한다.
- 모바일 메뉴가 hero 이미지 뒤에 가려져 클릭되지 않던 stacking 문제를 수정했다.
  메뉴 배경/클릭 영역이 이미지·지도 컨트롤 위에 표시된다.
- 설명이 없는 제목 아래 빈 문단, 긴 제목/FAQ 답변의 넘침, 관리자 카드 최소 폭을 보정했다.

## 확인

- 브라우저에서 320/390/768/1024/1440px × 홈·FAQ·예제·가이드·데이터·장치·요금·계정·포인트
  9개 경로의 컨테이너/헤더/푸터 좌표를 비교했다. 공통 프레임이 같고 페이지 가로 넘침이 없다.
- 각 화면 폭에서 FAQ·예제·가이드 제목의 시작 좌표가 일치한다.
- 데이터가 로드된 장치의 센서 그래프/수신 표도 320/1024px에서 확인했다.
- 320px에서 홈 모바일 메뉴를 열고 실제 내 데이터 이동/자동 닫힘을 확인했다.
- 관리자 사용자 표, 게시물 목록/편집 미리보기를 320px에서 확인했다.
  관리자 헤더는 1001/1100/1280/1440px 경계에서도 가로 넘침이 없다.
- FAQ 검색 동작 및 콘솔 오류 없음 확인. 데이터 변경/결제/USIM 충전 테스트는 하지 않았다.

이번 수정은 Shield 프론트만 변경한다. 스키마 9, 서버 로직, KC/GPS 수신 파싱은 유지한다.
