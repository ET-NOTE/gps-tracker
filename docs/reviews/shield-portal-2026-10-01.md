# Shield 포털 개편 (2026-10-01)

## 범위

사용자 시안에 맞춰 메뉴, 간결한 홈, 시작가이드, 예제/응용 프로젝트 목록,
내 데이터의 장치 사이드바, 내 장치, FAQ, 마이페이지, 포인트 내역을 구성했다.
응용 프로젝트는 사용자 답변에 따라 준비 중이며 가격/구매/유료 파일 배포는 없다.
온라인 포인트 결제는 기존과 같이 미연결 상태를 명시한다. 실제 결제나 1NCE
충전 테스트는 수행하지 않는다. GPS/KC 펌웨어와 API/DB는 변경하지 않는다.

## 콘텐츠 관리

- `/guide`는 관리자가 지정한 공개 기본 예제와 같은 콘텐츠/렌더러를 사용한다.
- `/examples`는 기본 예제와 준비 중 프로젝트를 소개한다. 카테고리는 전체 보기
  `/examples/all`, `/projects`에만 표시하고 검색과 함께 적용한다.
- 예제는 단계 제목/이전/다음, 단계별 다중 사진과 5초 자동 넘김을 지원한다.
  수동 넘김/일시정지, 포커스/마우스 오버/숨긴 탭 일시정지, 동작 줄이기를 반영한다.
- 파일 여러 개를 관리자가 업로드하고 모든 단계 또는 지정 단계에 배치한다.
  단계 이동/제거 시 사진·파일도 함께 이동/보존하며 저장 전 미리보기를 제공한다.
- 파일당 5 MiB, 게시물당 10개, 전체 100 MiB/500개. 코드/텍스트/PDF/ZIP만 허용.
  실행 대신 다운로드, no-store/nosniff/sandbox, 파일명 인코딩, 관리자 업로드 권한,
  동일 출처, 동시 처리/빈도 제한, 콘텐츠 해시 중복 제거를 적용했다.
- 초안/미첨부 파일은 관리자에게만 노출. 현재 공개 무료 예제에서 참조하는 파일만
  익명 다운로드 가능하다. 제거/비공개 전환 시 접근을 차단한다. 과거 내려받은
  사본은 회수할 수 없다. 한번 저장한 파일은 감사 이력용으로 유지한다.
- 지정 가이드가 비공개/유료 프로젝트가 되지 않도록 설정과 게시물 갱신을 직렬화한다.

## 데이터와 장치

- 비로그인, 장치 없음, 장치에 수신값 없음에서 합성 데모를 명시적으로 표시한다.
  조회 장애를 빈 데이터로 간주하지 않는다. 로그인 계정 변경 시 화면 상태를 초기화한다.
- 좌측 목록에서 선택한 장치 ID를 URL에 유지한다. 모바일은 가로 스크롤 목록이다.
- 센서 구성은 기존 동적 채널/단위/이전 구성 조회를 유지한다. 내 데이터 상단의
  고정 측정 카드는 시안에 따라 제거하고 그래프/위치/기록을 중심으로 표시한다.
- 내 장치에서 등록, 소유자 이름 변경, 최근 데이터, 마지막 유효 위치, LTE 마지막
  보고, USIM 잔량/기한/상태, 해당 장치의 충전 화면으로 연결한다.
- 온라인은 최근 3분 수신 여부다. 오프라인을 전원 OFF라고 단정하지 않는다.
  잔량 미조회와 0 MB를 구분하고 기한 경과/비활성/잔량 소진을 표시한다.

## 검증

- 격리된 etcom-hub preview `shield_test`에서 기존 수신 40, 운영 43,
  사진 24, WebSocket 7, 새 포털 39개 검증 통과. 통신사 주문 테스트는
  loopback mock에 한정한다. 실제 주문/결제는 호출하지 않았다.
- 포털 검증: 권한/출처, 파일 크기·형식, 초안/공개/해제, 수정 충돌,
  가이드와 비공개 전환 경합, 유료 파일 노출 차단, 장치 소유권/이름 변경 감사.
- 프론트 14개 테스트. 단계 제목/파일 이동, CSV/단위/센서 교체,
  USIM 잔량 미조회와 소진 구분을 검증한다.
- Windows 브라우저에서 비로그인 데모, 여러 장치와 미수신 장치 전환,
  관리자 Ctrl+V, 파일 2개 업로드, 저장, 자동 넘김/정지 및 다운로드 바이트 일치 확인.
  390px 모바일에서 장치 목록과 가이드 페이지 가로 넘침 수정/확인.
- 기존 사진 테스트의 고정 이미지가 이전 공개 브라우저 fixture와 중복되어
  미첨부 조건이 성립하지 않았다. 실행별 고유 합성 픽셀로 테스트를 격리했다.

## 운영 변경 및 복구

스키마 8은 post_files/post_file_links/site_settings만 추가한다. 기존 장치·계정·
센서/위치 테이블 구조는 바꾸지 않는다. nginx는 Shield 파일 업로드 주소에만
5 MiB body limit을 추가한다. 계정·도메인·단말 수신 설정은 유지한다.

`deploy-app.py --portal-upgrade`는 기존 스키마 1–7, 새 스키마 1–8, 정확한 nginx
추가 블록, fresh backup SHA, GPS binary/PID/시작 시각, 다른 nginx 설정과 Shield
환경 파일 해시 불변을 검사한다. VPS에서는 빌드하지 않는다.

백업은 첨부파일/참조/가이드 설정 테이블과 파일 바이트 SHA를 같은 DB snapshot으로
보관한다. offsite PostgreSQL 14 복원에서 건수·스키마·이미지/파일 SHA를 비교한다.
스키마 8 적용 후 SQLx 이전 바이너리로 단순 symlink rollback은 불가하다.
전진 수정 우선이며 DB 복구가 필요하면 신규 수신 데이터를 먼저 보존해야 한다.
