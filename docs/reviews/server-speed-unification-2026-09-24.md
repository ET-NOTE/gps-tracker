# 서버 좌표 속도 통일 — 2026-09-24

## 계약

- `speed_kmh`: 서버의 `server_coordinate_v1` 계산값. 계산 불가 시 null. 단말 속도 또는 브라우저 계산으로 대체하지 않는다.
- `reported_speed_kmh`: 단말이 보낸 유효 속도. 기존 DB 원본과 raw payload를 보존한다.
- `speed_interval_s`, `speed_reason`, `speed_source`: 계산 구간과 판정 근거.
- 계산은 DB 공통 함수 `location_speed_points_between`에서 수행한다. 별도의 전체 좌표 복제 테이블이나 펌웨어 변경 없이 과거 자료도 같은 규칙을 적용한다. 계산 결과를 원본에 덮어쓰지 않으므로 지연 삽입·삭제 후 오래된 계산값이 남지 않는다.
- REST 최신점·이력·페이지·공유, WebSocket, 집계 구간의 마지막/평균/최고속도, 일별 최고속도가 이 함수를 사용한다. 일별 평균속도는 기존의 이동거리/이동시간 정의를 유지한다.

## 계산 규칙

1. 같은 장치·소유자·GPS source 안에서 시간순으로 계산한다.
2. 최근 5초 안의 가장 오래된 점과 현재 점의 구면 거리를 사용한다. 그 구간에 이전 점이 없으면 직전 점을 사용한다. 유효 측정 구간은 3~60초다.
3. 같은 boot가 확인되고 두 점의 `up_ms`가 있으면 uptime 차이를 우선해 HTTP 도착 지연 영향을 줄인다. 없으면 서버 도착시각과 `age_ms`로 복원된 좌표 시각을 사용한다.
4. 3m 이내 변위는 0으로 처리한다. 유효 속도는 소수 둘째 자리 km/h다. 이 기준은 수 m 이내 느린 움직임을 구분하지 못할 수 있다.
5. fix 없음, 잘못된 좌표, 전달된 위성 수가 4 미만, boot/uptime 불연속, 60초 초과 공백, 인접 점 또는 계산 구간의 250 km/h 초과 이동은 미확인으로 처리한다. 충분한 정상 구간이 다시 확보되면 복구한다.
6. 조회 시작보다 65초 앞의 문맥을 읽으므로 일자·페이지·배치 경계가 속도를 바꾸지 않는다. 지연 자료가 들어오면 이후 점의 추정치는 바뀔 수 있다. 당시 실시간 값까지 영구 불변이라는 의미는 아니다.

## 화면

- 서버 속도만 사용하고 정차 클러스터 판정으로 속도를 덮어쓰지 않는다.
- 실시간 숫자와 마커는 동일한 마지막 좌표의 속도를 사용한다.
- 시커 집계 점은 구간 시작 대신 실제 마지막 좌표 시각과 그 좌표의 속도를 사용한다. 구간 최고속도는 원본 점의 서버 속도 최댓값이다.
- 미확인 속도는 그래프에서 0 대신 끊어진 구간으로 표시한다.
- 실시간 속도는 좌표가 90초 넘게 오래되면 숫자를 숨긴다. 갱신이 없어도 타이머로 판정한다.

## 한계와 범위

서버 계산 통일은 GPS 자체의 정확도 향상을 보장하지 않는다. 짧은 구간의 변위 속도이므로 굽은 경로·급가감속·큰 위치 오차에는 편향이 남는다. HDOP/수평 정확도/수신기 속도 정확도는 현재 배치 계약에 없어 사용하지 않는다. uptime/boot가 없는 구형 자료의 배치 간 전송 지연은 완전히 보정할 수 없다. 실제 차량과 계측기 비교가 필요하다.

KC 펌웨어·스캔·공개 진단과 prod 배포는 변경 범위 밖이다. prod 반영은 사용자의 별도 명시적 허가가 필요하다.
