# AI 운행 분석 안정성 및 FCM 문구 검토

## AI 변경

- 보고서 저장, 포인트 차감, 거래 장부, 사용 기록, 요청 영수증을 같은 DB 트랜잭션으로 확정한다. 외부 API 호출 중에는 차감하지 않는다.
- 계정당 한 분석, 서버 프로세스당 최대 4개 분석을 허용한다. 취소·실패 시 트랜잭션과 잠금이 해제된다.
- 브라우저는 계정/장치/날짜별 요청 UUID를 응답 확인까지 보관한다. 같은 요청을 재전송하면 기존 결과를 반환하고 재차감하지 않는다. 명시적으로 새 분석을 누르면 새 UUID를 사용한다. 구 클라이언트는 5분 안의 같은 장치/날짜 요청을 재사용한다.
- 삭제한 보고서의 요청 영수증은 남겨 삭제 후 재전송에 의한 재차감을 막는다. 장치/날짜가 다른 UUID 재사용은 거부한다.
- 분석에만 120초 HTTP 예산을 적용하고 나머지 API는 30초를 유지한다. 데이터 준비와 GPT 호출은 105초로 제한한다. 운영 nginx API proxy_read_timeout은 이미 120초다.
- 빈 응답, 거절, 토큰 제한으로 중단된 응답은 성공 보고서로 과금하지 않는다. 모델은 기존 운영 설정을 유지한다.
- 기존 서버 보정 속도를 사용한다. 기록 공백을 가로질러 정차/속도를 계산하지 않는다. 절전·기상 이벤트로 설명되는 공백과 원인을 알 수 없는 위치 기록 공백을 구분한다. GPS 기록 부재만으로 LTE 장애를 단정하지 않는다.
- UI는 구매 성공 응답을 바로 표시한다. 이력 재조회 실패 때문에 구매 성공이 실패로 보이는 경로를 제거하고, 다른 장치/날짜로 이동한 뒤 도착하는 결과를 무시한다.

## 검증 상태

- 정적 검사: Rust fmt와 clippy 통과. 일반 Rust 테스트 14개, 별도 DB 통합 테스트 2개(AI 거래·FCM 발송 정책) 통과.
- 격리 PostgreSQL: 보고서 저장 거부, 과금 후 사용 기록 저장 실패, 처리 중 취소, 소유자 변경, 잔액 변경, 동시 요청, 완료 요청 재조회, 보고서 삭제 후 재요청 검증 통과. 실제 포인트·외부 GPT 호출 없음.
- 웹 테스트 56개와 Vite 빌드 통과.
- 운영 DB 복원본의 위치 기록 85,681건과 사용자 6명의 일치 여부를 확인한 뒤 API 회귀 검사 26개 그룹 통과. 이력·KST 경계·소유권 분리·속도 통계·WebSocket·FCM 등록·진단 화면 호환을 확인했다.

## FCM 검토 결과 — 문구 제안, 미적용

서버의 현재 발송 템플릿과 웹 알림 설정, `flutter_app/lib/fcm.dart`, `notification_presentation.dart`, `main.dart`를 읽었다. Flutter는 서버 제목·본문을 그대로 표시한다. 문구 변경 대부분은 APK 갱신 없이 서버에서 반영할 수 있다. 실제 사용자에게 시험 알림을 보내지 않았다.

장치 이름/발생 시각 표시, 위치 확보와 운행 시작 구분, 배터리 % 미표시, 상담 답변 제목, 알림 중요도 분리는 이미 개선돼 있다. `online`은 앞선 수신 지연/오프라인 이벤트 뒤 데이터를 다시 받았을 때 생성하므로 현재 '연결 복구' 제목은 조건과 맞는다.

| 항목 | 미흡한 점 | 권장 문구 |
| --- | --- | --- |
| 수신 지연 | 데이터 미수신만 확인했는데 '연결이 돌아오면'으로 단절을 단정 | 최근 N분간 새 정보가 도착하지 않았습니다. 수신이 재개되면 최신 상태가 표시됩니다. |
| 절전 | 위치 갱신이 멈추는 정상 동작을 설명하지 않음 | 배터리 절약을 위해 절전 모드로 전환했습니다. 절전 중에는 위치 갱신이 잠시 멈춥니다. |
| 작동 재개 | '깨어났거나 다시 켜졌습니다'가 모호함 | 확인된 wake_cause에 따라 '정기 확인을 위해 작동을 재개했습니다' / '장치가 켜졌습니다'로 구분. 알 수 없으면 '장치가 작동을 재개했습니다'. |
| 위치 확인 지연 | 실제 조건은 여러 차례 GPS 미확보인데 단발성 지연처럼 안내 | 최근 위치 확인이 여러 차례 완료되지 않았습니다. 실내·지하에서는 GPS 수신이 어려울 수 있습니다. 장치와 안테나 상태를 확인해 주세요. |
| 전원 확인 | 누적 재시작 카운터의 증가를 수신한 시점인데 지금 발생한 고장처럼 읽힐 수 있음 | 전압 저하에 따른 재시작 기록이 확인되었습니다. 배터리와 전원 연결을 확인해 주세요. |
| 앱 알림 권한 | '알림이 꺼져 있습니다'는 어떤 알림인지 모호함 | '휴대폰에서 이 앱의 알림이 꺼져 있습니다' + '휴대폰 설정 열기'. 이 항목은 APK 갱신 필요. |

추가 발견: 예약 시작/종료·렌트카 반납 관련 이벤트는 생성되지만 현재 FCM 발송 정책의 허용 목록과 본문 템플릿에는 없다. 문구 개선과 별개로 알림 연결이 필요한 항목이다. 검토 요청 범위에서 발송 대상을 새로 활성화하지 않았다.

## 한계

실제 GPT 호출 성공과 휴대폰의 FCM 수신·소리·탭 동작은 이번 모의 검증으로 확인한 것이 아니다. 외부 호출 성공 후 프로세스가 종료되면 재시도 시 제공자 API 비용은 다시 발생할 수 있지만, 사용자 포인트는 보고서와 거래 장부가 함께 확정될 때만 차감된다.
