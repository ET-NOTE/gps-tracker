# 네이티브 지도 전환 — 사용자 설정

Flutter 앱의 기본 지도는 WebView를 유지하고, Android 테스트용 진행 방향 추적 화면에 Kakao Maps SDK 2.15.2를 연결했다. 홈 → 단말기 선택 → 도구 → 진행 방향 추적으로 진입한다. 지원하는 새 Android 앱에서만 항목이 나타난다. iOS는 이번 범위에서 제외했다.

## 카카오 Developers에서 필요한 작업

1. 기존 GPS 서비스의 카카오 앱에서 **네이티브 앱 키**를 확인한다. 키 값은 로컬 비공개 설정 파일로 전달한다. JavaScript 키나 REST API 키로 대체할 수 없다.
2. 해당 앱의 카카오맵 사용 설정이 ON인지 확인한다.
3. Android 앱 정보에 패키지명과 서명 인증서의 키 해시를 등록한다.
4. iOS까지 적용할 때는 번들 ID를 등록한다.

| 항목 | 확인한 값 |
|---|---|
| Android 패키지명 | `com.etcompany.gpstracker` |
| 현재 직접 배포 APK의 카카오 키 해시 (Base64 SHA-1) | `2zLjGqIesHW+GMtysRCxH1kQzTs=` |
| iOS 번들 ID | `com.etcompany.tracker` |
| 네이티브 앱 키 | 2026-10-09 수령, Flutter 저장소의 gitignored `android/maps.properties`에 저장 |

키 해시는 2026-10-08 생성된 `flutter_app/build/app/outputs/flutter-apk/app-release.apk`의 서명 인증서에서 추출했다. 인증서 SHA-1은 `DB:32:E3:1A:A2:1E:B0:75:BE:18:CB:72:B1:10:B1:1F:59:10:CD:3B`이다. Google Play App Signing이 별도 인증서로 서명한다면 **Play 앱 서명 인증서**의 키 해시도 추가해야 한다. 디버그 빌드를 사용할 때는 디버그 인증서도 별도로 등록한다. 인증서 해시는 공개 등록 정보이며 개인 서명 키가 아니다.

같은 release 서명으로 만든 모의 위치 시험 APK에서 지도 인증 HTTP 200과 지도 표시를 확인했다. ARM64 앱을 Android 34 에뮬레이터에서 실행했다. 테스트 좌표만 사용하며 서버 데이터 생성·실제 푸시 전송은 하지 않았다. 실제 휴대폰 주행 검증은 별도 필요하다.

표시 범위: 단말기 색상·이름·상태 마커, 마커 클릭 정보, 선택 단말기의 최근 경로·정지 지점, 미터 단위 지오펜스, 위성 지도, 북쪽 고정/진행 방향 전환. 지도 드래그는 추적을 중단한다. 이동 기록 분석·재생, 경로 계획, 펜스 편집, 로드뷰는 기본 웹 지도에서 사용한다. 이들 기능 전체를 네이티브로 옮겼다는 의미는 아니다.

좌표는 기존 웹 인증 세션에서 검증된 메인 프레임 브리지로 전달한다. 지도 화면에 토큰을 넘기거나 별도 서버 폴링을 추가하지 않는다. 지도 닫기·로그아웃·계정 변경 때 세션과 갱신을 중단하며 캐시/지연 좌표를 표시한다. 화면 표시용 전달량은 단말 100개, 경로 2500점, 클릭 지점 150개, 펜스 100개로 제한한다. 통신 누락 경로를 직선으로 이어 붙이지 않는다.

회전은 단말기 heading을 우선 사용하고, 없으면 8~500m 이동한 연속 좌표의 방위각을 쓴다. 3km/h 미만, 2분 초과 위치, 캐시 또는 GPS 미수신은 회전을 멈춘다. 359°→1°는 짧은 방향으로 보간한다. SDK의 지도 회전 방향은 방위각과 반대이므로 `(360 - heading) % 360`을 전달한다.

웹 변경은 API/DB를 건드리지 않는 별도 정적 파일 배포로 진행하며, 이전 웹 디렉터리를 보존한다. FCM의 24시간 미수신 후 단절당 1회 정책은 변경하지 않는다.
