## 내용과 동작의 정합성

- 배터리 알림 생성과 발송 재확인에 사용자가 설정한 전압을 적용한다. 기본 3500mV이며 0mV 같은 유효하지 않은 측정은 알림을 만들지 않는다. 배터리 전압 설정은 설명이 있는 접기 영역으로 옮겼다.
- 움직임 센서에 의한 wake는 `motion_alert`, 기타 wake는 `wake_alert`로 제어한다. 동일 이벤트에서 두 알림을 중복 생성하지 않는다. 센서 깨움을 실제 차량 이동으로 단정하지 않는다.
- 알려진 사용자 알림만 발송하며 `stuck`, `lost`, 미정의 이벤트는 진단 기록에만 남긴다.
- enqueue와 매 발송/재시도 직전에 소유자·현재 설정·최근 telemetry 및 최신 상태 이벤트를 다시 확인한다. 연결 복구, 절전, 배터리 회복, GPS 재확보, 구역 상태 반전 등으로 낡아진 대기 알림을 취소한다.
- 연결/작동 알림은 15분, 배터리·전원·GPS와 구역 출입은 1시간, 상담은 24시간까지 유효하다. FCM TTL에는 남은 시간을 넣는다. 상태별 tag와 앱의 안정된 ID로 알림함의 이전 상태/재시도를 교체한다.
- 설정 PATCH는 저장된 값과 합친 결과를 트랜잭션에서 검증한다. 수신 지연 1~30분, 연결 확인 5~120분이며 뒤의 시간이 앞보다 길어야 한다. 웹은 저장 중 중복 조작을 막고, 실패 시 실제 저장값으로 복구하며 재시도 안내를 표시한다.

코드는 `services/notification_policy.rs`, `notification_relevance.sql`, `services/fcm.rs`, `routes/notifications.rs`, `routes/ingest.rs`, 웹 `NotificationSettings.jsx`, 앱 `notification_presentation.dart`와 `fcm.dart`에 있다. 정책과 OS 채널/TTL의 한계는 [FCM_SETUP.md](../FCM_SETUP.md)에 정리했다.

## 검증 및 KC 유지

- Hub: Rust fmt / clippy `-D warnings`, 일반 테스트 8개, 격리 PostgreSQL + 모의 FCM 통합 테스트 1개, 웹 테스트 29개 통과.
- 모의 FCM: 부분 성공 보존, 503 재시도, lease 복구, 계정 변경, 복구 후 offline 취소, 내부 이벤트 제외, 모션 설정, 소유자 변경, 만료, 배터리 회복/사용자 임계치, enqueue 실패 원자성 확인. 실제 FCM 테스트 메시지는 보내지 않았다.
- dev 및 운영 복원본: API 회귀 25개 그룹 통과. 사용자 전압 기준 반영·잘못된 설정의 400/기존 값 보존·0mV 방어를 추가했다. 공개 dev의 기존 19개 그룹도 재검증했다.
- 운영 위치 이력 83,829행을 복원했고 전체 행 해시가 원본과 일치했다. Timescale 2.19.3 복원은 기존에 검증한 일관된 스냅샷의 logical dump + hypertable CSV 방식을 사용했다.
- KC 익명 no-fix ingest/scan/pairing, 익명 DHT, 공개 진단을 검사했다. firmware·KC 진단 HTML·DB migration 변경이 없다.
- 운영 전환 후 env/nginx/장치 reset·beep·post_interval 및 소유권 상태 해시가 그대로임을 확인했다. 공개 홈/장치/상담 경로, 정적 파일 36개 해시, KC HTML 해시, HTTP/HTTPS ingest의 정상적인 오류 응답을 검증했다. 이번 전환에는 자동 롤백이나 웹 오류가 없었다.
- 앱: analyze 진단 0건, 테스트 7개, APK/AAB 빌드와 서명 검증 통과. 기존 운영 인증서와 동일하다.

빌드는 etcom-hub, Android 빌드는 Windows에서 수행했다. VPS에 빌드 도구나 상시 환경을 추가하지 않았다. 운영 복원 DB와 임시 업로드 경로, Hub의 임시 PostgreSQL 컨테이너/네트워크는 검증 후 정리했다.
