## 실행 중인 가상 장치

- UID: `dev-sim-windows-20260924`, dev 장치 ID: `3013`.
- 별도 dev 검증 계정에 연결했다. 기존 장치나 사용자 계정의 소유권은 바꾸지 않았다.
- `ops/dev_gps_simulator.py`: 표준 Python만 사용. 목적지는 `https://dev-gps.serial.kr/gps-tracker/ingest`로 고정하고 redirect를 거부한다.
- 2초마다 좌표를 생성하여 10초마다 HTTP 배치를 전송한다. 7분 이동 + 6분 정차를 반복하며 약 1m의 정차 흔들림을 포함한다.
- 처음 20분의 더미 이력을 최대 200점씩 제한해 전송한 뒤 실시간 모드로 이어간다. 재전송은 `up_ms`를 유지하고 `age_ms`를 다시 계산한다.
- 가상의 서울 시청 주변 경로이며 실제 사람/차량 위치가 아니다. 이동선이 실제 차로와 일치한다는 뜻도 아니다.
- Windows 백그라운드 프로세스로 24시간 실행한다. PC 종료·절전 중에는 송신되지 않으며 재부팅 자동 시작은 설정하지 않았다.
- 로그는 1MiB × 최대 4개로 회전한다. 가상 장치의 DB 기록은 남겨 seeker 확인에 사용한다.

실행:

```powershell
.\ops\Start-DevGpsSimulator.ps1 -DurationHours 24
```

중지:

```powershell
.\ops\Stop-DevGpsSimulator.ps1
```

상태/최신 페이로드/로그: `%LOCALAPPDATA%\GPS-DevSimulator\state.json`, `latest-payload.json`, `sender.log`.
전용 로그인 정보는 같은 폴더의 `login-private.json`에만 보관하며 Git에 포함하지 않는다.
실시간 검증: `node ops/verify_dev_stream.mjs`. 로그인 후 자신의 가상 장치 WS 3회 수신과 REST 이력·활동 날짜를 검사한다.

## 수정한 문제

1. 컴팩트 seeker가 일별 통계 생성 전 새 장치의 날짜를 표시하지 못했다. 원본 점 기반 `active-dates`를 사용한다.
2. 월 조회의 지연 응답이 선택한 일간 경로나 닫힌 seeker를 덮어쓸 수 있었다. 요청 세대를 무효화하고 장치 전환 시 seeker를 새로 마운트한다.
3. 화면의 정차 판정이 150m 안의 5점이라는 개수 기준이라 고빈도 이동도 정차가 됐다. 서버와 같은 50m/5분 기준으로 바꾸고 계산을 선형 시간으로 줄였다.
4. seeker/재생 거리에서 장시간 수신 공백·비현실적 좌표 도약·정차 흔들림을 제외한다. 집계로 표시한 거리는 원본 전체 거리와 구분하여 `표시 경로 거리`로 표시한다.
5. GPS 원본 속도를 화면 계산에 보존하고 WS 배치의 점마다 속도를 전달한다. 0도 위도/경도도 유효 좌표로 처리한다.
6. 순서가 섞인 배치의 WS 대표 좌표는 마지막 배열 원소가 아니라 최신 시각의 수신 점을 사용한다. 빈/중복 제거된 배치는 위치 이벤트를 만들지 않는다.
7. 상세 seeker에 새로고침을 추가했다. 컴팩트 월간은 최근 10,000개 전송만 조회하던 제한을 없애고 전체 월의 5분 집계를 표시한다. 일간 원본 한도는 10,000개 전송이며 이 한도를 넘는 초고빈도 장치의 전체 일간 페이징은 잔여 항목이다.
8. 기존 Rust 포맷 및 Clippy 경고를 정리했다. 포맷만 바꾼 커밋을 별도로 분리했고, 사용하지 않는 내부 함수/투영 필드를 제거했다. HTTP/JSON 응답 계약은 유지한다.
9. 상세 seeker가 정차 GPS 점 개수를 정지 횟수로 세고 선택 범위의 운행시간에 하루 전체 통계를 사용했다. 연속 정차 구간 수와 선택 경로의 이동/정차 시간을 계산한다. GPS만으로 엔진 공회전을 판정할 수 없어 `공회전` 표기도 `정차시간`으로 수정했다.

## 검증 근거

- 프런트 회귀 11건: 인증 격리 5건 + 고빈도 저속 이동/정차/공백/속도/WS 순서/선택 범위 KPI 6건.
- Python 시뮬레이터 3건: 재전송 식별자·age 계산, dev 장치 제한·redirect 거부, 이동/정차 주기.
- Rust 3건: 정차/저속/공백과 뒤섞인 배치 대표 좌표 회귀. Hub에서 `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` 통과.
- Windows→공개 dev HTTPS와 WebSocket: 배치 수신, 점별 속도, 두 원본 행의 전체 GPS 점, 활동 날짜 확인. 초기 REST 지연 44~71ms.
- dev에만 임시 100,000점(1,000행 × 100점) 데이터를 생성하여 DB 실행 계획을 측정한 뒤 해당 임시 장치를 제거했다.
  - 최신 좌표 254ms, 1분 집계 198ms, 활동 날짜 267ms.
  - 4MiB work_mem에서 임시 디스크 정렬이 발생했다. 이 결과가 수백만 점/동시 다수 사용자 성능을 보장하지는 않는다.

## 남은 항목

- 더미 송신 장기 관측은 진행 중이며 24시간 무중단 검증 완료를 의미하지 않는다.
- 실제 펌웨어의 RF 순단·절전·재부팅·시계 오차는 시뮬레이터로 검증할 수 없다.
- dev 전용 외부 서비스 키 마련 전 AI 분석은 비활성 상태다. Kakao 브라우저 지도 앱은 아직 공용이다.

- 더 큰 데이터의 조회 계획 최적화와 운영 반영은 별도 단계다. 물리 분리는 사용자 결정에 따라 보류한다.
