## 공통 구조 판단

- `theme.js`는 이미 색상, 간격, 반경, 그림자, z-index 토큰을 정의한다. 정의 부족보다 **사용 일관성과 상태 계약**이 문제였다.
- 검토 전 src의 JS/JSX/CSS에서 hex 리터럴 345회, 97종. 지도 속도 범례, 장치 팔레트, 인쇄 색상도 포함하므로 이 전체를 primary로 치환하면 안 된다.
- 상수/공유 서비스는 전역이라는 이유만으로 제거하지 않았다. auth 갱신·query cache는 세션 가드와 초기화가 이미 있다. 시커의 사용하지 않게 된 주소 캐시는 제거하고, 장치 색상 캐시 외부 변이는 막았다.
- 공통 시간·요약 정규화는 `src/lib/seeker.js`, 상세 조회 상태는 `src/useSeekerPoints.js`로 분리했다. 두 시커의 지도 목적은 유지한다: 홈은 빠른 원본 일간 탐색, 운행은 기간·요약·재생·비교.
- 상세 일간의 거리/정차/운행시간은 여전히 **선택한 대표점으로 추정**한다. 서버의 개별 좌표 속도와는 다른 지표다. 이를 화면에 명시했으며, 서버 원본 기반 구간 통계 API로 완전히 통일한 것은 아니다.

## 남은 개선 (이번에 모두 완료했다고 보지 않음)

1. **P2 상태 의미 통일**: `components/fleet/SummaryChips.jsx`는 wake 이벤트를 시간 검사보다 먼저 판정한다. 오래된 wake도 운행으로 남을 수 있다. `colors.js`의 통신/절전 상태와 `lib/liveMotion.js`의 GPS 이동 상태를 구분한 하나의 표시 계약이 필요하다.
2. **P2 계정 설정 저장 경계**: 상세 시커의 `seeker_speed_color` / `seeker_show_stops`는 계정 구분 없는 localStorage seed이며 hydrate 후 effect가 PATCH한다. 계정별 키, 사용자 조작 시 저장, 저장 실패 표시, prefs query 통합을 다음 단계로 진행한다. 로그인 데이터 격리 문제 전체가 미해결이라는 뜻은 아니다.
3. **P2 비동기 AI 결과**: 상세 시커의 분석 요청 중 날짜를 변경하면 이전 날짜 결과를 현재 패널에 넣을 수 있다. 요청 당시 날짜/계정과 응답을 연결해야 한다. 이번 검증에서 유료 분석은 실행하지 않았다.
4. **P2 지도 전역 콜백**: `KakaoMap.jsx`의 `window.__btw_*`는 지도별 소유권이 없고 gap 텍스트가 지도 해제까지 누적된다. 여러 지도를 동시에 쓰기 전에 인스턴스별 DOM 이벤트/제한된 캐시로 교체해야 한다. 현재 단일 지도 흐름은 유지했다.
5. **P2 원본 기준 통계**: 상세 시커의 요약 간격에 따라 추정 거리·정차·운행 경계가 달라진다. 원본 구간 집계와 서버 운행 경계를 제공하면 컴팩트/상세 간 의미를 더 일관되게 만들 수 있다.
6. **P3 공통 UI 적용 확대**: Corporate/Rentcar/Admin 및 Kakao HTML 툴팁에 직접 색상/크기, FormField의 label 연결 누락 등이 남아 있다. 범례색/장치색/행동색을 구분하면서 Button/Field/Panel 도입을 확대해야 한다.
7. **P3 화면 구조 분리**: 검토 전 SeekerSheet 2,298줄, Dashboard 1,630줄. 조회/월간 카드 일부를 줄였지만 재생·달력·AI·연구소가 상세 패널에 남아 있다. 한 번에 갈아엎기보다 기능별 테스트를 추가하며 분리한다.
