# Shield 전용 서비스 1차 구현 · 2026-09-28

## 결정과 현재 범위

- 도메인 `shield.serial.kr`, 정적 React 프론트엔드 `shield-web/`.
- 같은 저장소의 **별도 Rust 바이너리/프로세스 `shield-api`**. 기존 API에 Host별 테넌트 분기를 넣지 않는다.
- PostgreSQL 엔진은 공유하되 `shield_prod` DB와 `shield_app` 역할, 계정·세션·단말 키·데이터를 독립 관리한다.
- 최초 가입은 **초대코드**. 공개 가입, 이메일 인증·비밀번호 복구, 결제·실제 USIM 충전은 이번 단계에 포함하지 않는다.
- 기존 GPS 계정의 비밀번호/JWT/FCM 토큰을 복사하지 않는다. 단말의 소유자 연결도 자동 복제하지 않는다.
- API `127.0.0.1:3043`, DB 풀 최대 4개, 서비스 메모리 한도 128 MiB. 프론트엔드에 별도 Node 운영 프로세스가 없다.
- 운영 배포, 실제 단말 전송 주소 변경, 과거 데이터 이관은 **아직 수행하지 않았다**. 사용자의 명시적 운영 승인 후 진행한다.

## 구현

- 초대코드 7일/1회 사용, Argon2 비밀번호, DB에 해시만 저장하는 세션. 운영 쿠키는 `__Host-shield_session`, Secure/HttpOnly/SameSite=Strict/Path=/.
- 장치별 독립 키와 일회용 등록 코드. 등록 전 수신 거절, 계정 귀속 후 소유자만 조회/CSV/실시간 갱신 가능. UID만으로 장치를 가져갈 수 없다.
- UTC GPS 표본 최대 8개, 센서 표본 최대 32개. 범위/시간/순서 검증, 동일 메시지 및 겹치는 표본 중복 제거. 센서 UTC 없는 상태 보고는 측정값을 만들지 않는다.
- 기존 `0062/0063/0064` SQL을 그대로 포함해 좌표 전개·서버 속도 계산을 재사용한다. GPS 원본 마이그레이션은 변경하지 않는다.
- 홈(명시적인 데모), 시작 가이드, 예제 검색/분류, DHT11 스케치·Python 전송 예제, 소유 장치 선택, 최근 온습도/신호, 5분 평균 차트, 지도, 기록 페이지·전체 범위 CSV.
- 최근 유효 온습도는 상태 보고와 별도로 측정 시각을 유지한다. `CSQ=null/99/-1`은 미확인. PV는 입력 전압으로 표시한다.
- 조회 최대 7일, 지도 최근 1,000점, CSV 최대 50,000행(전체 페이지 성공 후 파일 저장). 수신 공백·무효 fix·속도 불연속은 경로를 잇지 않는다.
- 지도 데이터만 갱신하여 사용자의 확대/이동 상태를 보존한다. 장치·계정 전환 시 기존 데이터와 진행 중 요청을 정리한다.
- USIM은 전용 안내 화면과 소유 장치 선택을 제공한다. 통신사 잔량 조회는 미연동 상태를 명시하며 예시 잔량·상품·결제 버튼을 실제 기능처럼 표시하지 않는다.
- 기본 Cargo 빌드/실행은 GPS 바이너리를 유지한다. Shield는 `--features shield --bin shield-api`로만 빌드한다.

## 검증

1. Rust 단위 검사 2개, clippy 경고 없음, release 빌드.
2. 별도 PostgreSQL 16 테스트 DB에서 통합 검사 40개: 초대코드 동시 소비, 계정 격리, 장치 등록, 키 검증, UTC·범위, 중복, 페이지 정합, 서버 계산 속도, 세션 폐기.
3. WebSocket 검사 7개: Origin·로그인 확인, 소유자 전용 이벤트, 다른 계정 차단, 로그아웃 후 즉시 다음 이벤트 차단.
4. 프론트엔드 검사 7개: CSQ·경로 단절, CSV 이스케이프, 모든 페이지, 중간 실패·반복 커서·취소. npm audit 보고 취약점 0개.
5. VPS와 같은 PostgreSQL **14**의 별도 컨테이너에서 운영형 역할과 HBA 검증: 마이그레이션/공용 GPS 함수 실행 성공, Shield 역할의 다른 DB 연결 거절, 일반 GPS 역할의 Shield DB CONNECT 거절, 관리 권한 없음.
6. nginx 설정 문법 검사 성공(러너의 임시 인증서 사용). 실제 VPS 전체 설정에 대한 `nginx -t`는 운영 적용 직전 다시 수행해야 한다.
7. 브라우저: 로그인·로그아웃, 2개 장치 선택과 빈 장치의 이전 값/지도 제거, 선택 유지, 예제 검색, 데스크톱/390px 모바일 표시, 실시간 합성 수신 확인.

Windows 합성 전송 5회에서 GPS 30점 수신과 자동 갱신을 확인했다. 확대 레벨 16은 수신 후에도 유지됐다. 빌드된 정적 번들의 브라우저 오류는 없었다. CSV 내용·전체 페이지 처리·실패 시 저장 방지는 자동 검사로 확인했으나, 인앱 브라우저의 실제 파일 저장 완료 이벤트는 확인되지 않아 일반 브라우저 저장 검증이 남아 있다.

운영 VPS 확인 시 가용 메모리 약 1.2 GiB, 디스크 여유 4.3 GiB(90% 사용). 시험 API 메모리는 약 20 MiB였으나 실제 동시 사용자 부하는 별도 관찰이 필요하다. 이번 작업에서 운영 디스크 파일을 정리하거나 서비스를 재시작하지 않았다.

실제 운영/개발 DB 로그인 역할 `gps_tracker_app`, `gps_tracker_dev_app`는 superuser/createdb/createrole 권한이 모두 없는 것으로 읽기 전용 확인했다. 운영 API SHA256은 `81214c4f4c49ee361a92271f913271ccc9bc633b7d0e41e51807df945cae79d9`로 유지됐고 `/diagnostic`은 HTTP 200이었다.

## KC 및 기존 GPS 영향 범위

- 기존 `/ingest`, `/ingest/shield`, `/diagnostic`, 스캔·페어링·FCM 라우트/워커 코드는 수정하지 않는다. 새 Shield `/ingest/shield`는 별도 프로세스/DB의 동명 경로다.
- `idf-caltest`, KC 빌드, `03_8`, 실제 동작 중인 `03_10` v11 펌웨어는 변경·업로드하지 않는다.
- 운영 `gps.serial.kr/arduino-shield`와 그 계정 귀속·공개 상태 예외를 유지한다.
- 운영 DNS/nginx/DB/HBA는 아직 바꾸지 않았다. 추가 HBA 규칙은 `shield_app`만 매칭한다. PostgreSQL 재시작 대신 설정 reload를 사용한다.
- 같은 PostgreSQL 엔진/VPS/관리자는 공유한다. 논리 DB 및 서비스 권한 분리이며 관리자·스토리지 장애까지 독립된 물리 격리는 아니다.

## 그 다음 단계 (분리 배포 이후)

- 실제 쉴드에 고유 UID/키와 **인증서 검증이 되는 HTTPS**를 반영하고 SIM7080G로 실기 검증. 현 v11에 도메인만 바꾸면 새 API에 인증되지 않는다. 시험 중인 기존 GPS 업로드는 승인된 전환 시점까지 유지한다.
- `user@user.com`도 신규 Shield 계정으로 가입 후 기존 쉴드 소유자 확인을 거쳐 이관한다. 과거 위치/센서 복사는 단말·소유자 범위를 제한하고 건수/UTC/중복 해시를 검증한 후 수행한다. GPS 원본 삭제는 포함하지 않는다.
- 실제 통신사 USIM 조회와 ICCID 소유 관계를 연결한 뒤 잔량 화면 활성화. 결제/충전은 상품·요금·유효기간·실패 복구·멱등성 확정 후 별도 구현.
- 초대 운영에서 계정 복구 절차·이메일 확인·보존 기간·서비스 약관을 확정한 뒤 공개 가입 검토.
