## 편집/공개 동작

관리 → 게시물 → 편집에서 본문 영역 Ctrl+V, 파일 선택, 파일 드롭으로 사진을
추가한다. 단계 뒤 버튼, 삽입 위치 선택, 사진 설명/캡션, 사진 순서 및 제거,
단계 이동/제거, 저장 전 미리보기를 제공한다. 단계 이동 시 사진도 이동하고,
단계 제거 시 해당 사진은 이전 삽입 위치에 보존한다. 코드 입력은 별도이다.
공개 페이지와 미리보기는 같은 본문 렌더러를 사용한다.

원본 PNG/JPEG/WebP는 최대 10 MiB. 브라우저에서 방향을 적용하고 최대 1,600px로
줄인다. 서버는 크기·형식을 다시 검사하고 메타데이터를 제거한 WebP로 재인코딩한다.
저장 한 장 1.5 MiB, 게시물 20장, 전체 100 MiB/1,000장 제한 및 해시 중복 제거.
변환은 암호 해싱과 작업 예산을 공유해 메모리 사용량을 제한한다.

저장되지 않은 사진/초안 사진은 관리자만 조회한다. 현재 공개 게시물에 참조된
사진만 익명 조회가 가능하고, 비공개 전환/마지막 공개 참조 제거 시 접근을 막는다.
no-store/nosniff 응답. 기존에 내려받은 공개 사진 사본까지 회수하지는 못한다.
한 번도 게시물에 저장하지 않은 업로드만 24시간 후 다음 업로드 때 정리한다.
저장 이력이 있는 사진은 감사 기록을 위해 유지한다. 감사 로그에는 이미지 원문을
넣지 않고 해시 ID와 크기·변경 내용을 기록한다.

## 검증

- Rust 단위 5, Clippy `-D warnings`, GPS 기본 타깃 check, 프론트 11 및 릴리스 빌드 통과.
- 미리보기 API 24개: 권한/출처, SVG·손상·과대 이미지 거절, 중복 제거,
  초안/발행/비공개/사진 제거에 따른 접근 변경, 수정 충돌, 참조·배치 검증.
- 1,600×1,600 합성 노이즈 사진 처리 후에도 서비스 정상. 컨테이너 메모리 최대
  31,436,800 bytes(약 30 MiB), OOM 0. 설정 한도 128 MiB.
- Windows 브라우저에서 실제 이미지 Ctrl+V 및 파일 선택, 두 단계 사이 이동,
  미리보기, 저장, 공개 페이지 이미지/캡션 표시 확인. OS 파일 드래그 자체는
  자동화하지 않았으며 파일 드롭 코드는 같은 업로드 경로를 사용한다.
- 운영 HTTPS에서 128 KiB를 넘는 합성 사진 업로드 및 관리자 조회 성공,
  메타데이터/해시/응답 헤더·익명 차단·SVG 거절 확인. 운영 게시물 7개와 각
  revision 1은 그대로 유지했다. 시험 이미지는 미첨부 비공개 상태 1개이다.
- 운영 관리자 화면에 새 편집기 표시 확인. 실물 쉴드 v12 수신/유효 좌표 확인.
  결제/1NCE 충전 요청 및 포인트 장부 0건. 이번 검증은 결제 API를 호출하지 않았다.
