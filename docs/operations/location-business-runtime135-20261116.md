## 구현

- 기존 `GET /corporate/subject-mappings`에 `before`, `status`, `limit`을 추가했다. 서버 기본200건은 이전 클라이언트와 호환하며 화면은50건씩 최신순으로 조회한다. 최대200·양수 커서·5상태만 허용하고 소유자 덮어쓰기 등 알 수 없는 필드는 거부한다. 한 건을 추가로 읽어 실제 다음 페이지가 있을 때만 `next_before`를 반환한다.
- 회사 소유자/위임 관리자 권한을 먼저 확인하고 해당 회사의 행만 읽는다. 일반 구성원·부서 관리자는 거부한다. 기존 읽기 전용 트랜잭션·2개/20초 조회 보호·연결 취소를 사용하며 정상 빈 조회도 명시적으로 종료한다. 회사 목록 응답에 위치 좌표를 추가하지 않는다.
- 신규 요청용 최근200개의 차량-SIM 연결에 **현재 페이지의 과거 연결**을 함께 반환한다. 기존 연결이 최신200개 밖에 있어도 정정·재동의 양식에서 사라지지 않는다. 타사 연결은 포함하지 않는다.
- 상태 필터, 이전/다음, 처음/새로고침, 목록 취소를 추가했다. 이동/실패 중 이전 행은 숨기고 실패와 빈 목록을 구분한다. 필터·페이지 변경 시 편집 및 위치 선택을 초기화한다. 위치 조회는 선택 행/revision에 묶고 비활성 캐시를 남기지 않는다. 새로고침·필터 변경·화면 종료 시 이전 위치 요청을 중단하고 늦은 응답은 표시하지 않는다.
- 정정·재동의 후 선택한 상태의 첫 페이지로 돌아간다. 철회는 일반 정정으로 우회할 수 없고, 기존 본인·차량·기간 그대로 새 본인 확인을 받아야 한다. 초·밀리초를 포함한 원래 기간은 재동의 요청에 보존한다. 기존 서버 동의/통보 정책은 바꾸지 않았다.

## 범위와 남은 제한

- 회사의 **위치정보주체 연결 목록**을 페이지화했다. 새 요청을 위한 모든 과거 차량-SIM 연결 검색은 구현하지 않았으며 최근200개와 현재 페이지 연결을 제공한다. 활성 직원 선택 목록, 개인 연결 목록과 제공 통보 탐색은 이번에 바꾸지 않았다.
- 상태 필터는 조회 시점 기준이며 고정된 시점의 전체 목록을 보장하지 않는다. 다른 사용자의 상태 변경이 있으면 새로고침으로 다시 확인한다. 최근 폴링은 이전처럼30초 간격이다.
- 브라우저 위치 요청 중단/옛 좌표 제거와 회사 목록 SQL 취소는 별개다. 위치조회 SQL 취소를 새로 보장한 변경은 아니다. 과거에 제공된 자료를 회수하거나 이미 발송한 통보를 삭제하지 않는다.
- 정책·실제 정보주체·회사 공용 자료/외부 사본·대리인 확인·보관/파기 근거는 여전히 확정이 필요하다. 목록 탐색 개선으로 실제 업무 전체의 완결성을 선언하지 않는다.
