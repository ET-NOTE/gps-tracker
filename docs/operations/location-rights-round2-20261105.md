# 위치정보 권리 처리 2차 — SIM 단위 DB 파기 실행기

2026-11-05 · `codex/location-business-prep` · **격리 검증 완료, 운영 미배포**.

후속 상태: [3차 라운드](location-rights-round3-20261105.md)에서 다른 SIM 집계 보존 문제를 해결하고 제한된 운영 배포 및 `sss` 실제 파기 검증을 완료했다. 아래 내용은 2차 종료 당시 기록이다.

사용자는 `sss`에 쌓인 자료(user@user4.com 소유 이력 포함)를 잃어도 되는 시험 자료로 지정했다. 이 승인을 계정 전체 또는 다른 SIM 자료의 삭제 승인으로 확대하지 않았다. 운영 서버는 읽기 전용으로 점검했고, `sss` 실제 자료만 암호화된 SSH 스트림으로 격리 DB에 옮겨 파기했다. 운영 DB·웹·API·펌웨어와 dev/Shield는 변경하지 않았다. 전체 DB 백업이나 운영 인증키 복제는 하지 않았다.

## 구현한 범위

- `0084_device_data_erasure.sql`: 장치별 지속적인 쓰기 차단과 작업 이력. `blocked → primary_erased → active_db_verified` 단계로 진행하며 자동 재개하지 않는다.
- `ops/erase_device_data.py`: 기본은 읽기 전용 미리보기. 실행에는 정확한 장치 ID·소유 계정·이름·전체 SIM 번호, 작업 UUID와 `--execute`가 필요하다. 같은 UUID로 중단 지점에서 재시도한다. 이 명령은 **한 SIM의 모든 소유자 이력**을 대상으로 하므로 일반 회원의 권리 요청이나 계정 삭제 API에 연결하지 않았다.
- 수집 API: 인증과 재전송 방지를 유지한 채 차단된 SIM에는 서명된 `ok:true, stored:false, privacy_blocked:true` 응답을 보낸다. 위치 저장·이벤트·명령 실행·페어링 상태 갱신을 생략한다. 이 응답은 서버에 저장하지 않았다는 뜻이며, 단말기 측위·RAM 버퍼까지 중지됐다는 뜻은 아니다.
- DB 쓰기 차단: 수집뿐 아니라 늦게 끝난 통계·AI·지점 방문·보정·알림 작업, 공유 링크 생성과 최근 위치 캐시 갱신을 차단한다. 실행 중인 쓰기 트랜잭션이 끝난 뒤 차단을 확정하고, 대기 중 소유권이 바뀌었으면 삭제를 거부한다.
- 원본·이벤트·일별 통계·운행 메모·AI 결과·개인 펜스·방문 기록·보정/배정 기록·대기 알림·공유 링크·최근 위치 캐시를 대상으로 처리한다. Timescale 집계는 별도 갱신 후 잔여 행을 검사한다. 잔여 행이 있으면 검증 완료로 넘어가지 않는다.

**SIM 논리 장치, 하드웨어 인증키, 계정, 차량·SIM 배정 이력은 유지한다.** 계약·지출·결제·AI 과금 재시도 영수증은 이 실행기의 파기 대상이 아니다. AI 본문 삭제 시 과금 영수증의 분석 FK만 NULL이 된다. 이 구분은 법적 보존 기간을 확정했다는 뜻이 아니다.

첨부파일이 있거나 알림 발송 lease가 진행 중이면 원본 삭제 전 거부한다. 파일 삭제 기능, 이미 전달된 알림·AI 사본, 로그·백업·다운로드본 및 클라이언트 캐시까지 완료했다고 표시하지 않는다. `external_copies_verified`는 false로 고정했다. `active_db_verified`도 이 실행기에 열거된 DB 자료의 검증 결과일 뿐, 계정 종료나 모든 개인정보 파기 완료가 아니다.

## 격리 시험

운영과 같은 **PostgreSQL 14 / TimescaleDB 2.19.3**을 내부 전용 Docker 네트워크에서 사용했다. 외부 FCM·AI·결제 자격 증명은 주입하지 않았다. 실제 자료는 tmpfs DB로만 전달했으며 좌표 덤프 파일을 남기지 않았다. 시험 종료 시 해당 컨테이너와 내부 네트워크를 제거한다.

`ops/test_device_erasure.py` 검증:

- 대상 소유자·SIM·이름 불일치 거부, 기본 미리보기 무변경.
- 이미 쓰기 중인 작업을 기다린 후 차단, 차단 이후 늦은 쓰기 거부.
- 압축 청크의 원본, 과거 소유자/현재 소유자/NULL 이력과 연결된 파생 자료 삭제.
- 진행 중 알림·첨부파일이 있으면 원본 보존, 실패 후 차단 유지.
- 원본 삭제 뒤 집계가 남으면 완료 거부, 재시도 후 집계 제거, 중복 실행 결과 유지.
- 다른 SIM의 원본·일별 통계·집계 전체 행 지문 유지, SIM 식별 및 차량 연결 유지.
- 서명된 차단 응답, 잘못된 서명 거부, 같은 카운터 재사용 거부, 같은 인증키로 다른 SIM 정상 수신.
- 원본 없이 남은 대상 집계 삭제. **다른 SIM의 집계 입력이 사라졌거나 달라졌으면 갱신 거부**하여 그 SIM의 집계만 남은 이력을 보호.

Rust clippy 경고 0, 단위 시험 35개 통과(격리 DB 별도 조건 시험 2개 ignored), debug 빌드 성공. 이전 `ops/test_privacy_requests.py`의 인증·계정 경계·동시성·삭제/탈퇴 허위 완료 차단 회귀도 통과했다. 웹 수정과 새 APK/펌웨어 빌드는 이번 범위에 없다.

## 운영 적용 전 발견한 문제와 다음 순서

운영의 `sss` 1분 집계는 1,849행이고, 현재 원본으로 재계산한 사본은 1,564행이다. 차이 285행의 원인을 원본 보존 정책·과거 수정·집계 갱신 이력과 함께 확인해야 하며, 이 차이만으로 손상이라고 단정하지 않는다.

더 중요한 점은 같은 기간 **다른 SIM에도 세 집계 모두 원본 fix 개수와 불일치하는 버킷이 존재**한다는 것이다. `refresh_continuous_aggregate`는 지정 시간대의 다른 SIM에도 영향을 준다. 무조건 갱신하면 사용자가 폐기를 허용하지 않은 다른 SIM의 집계만 남은 이력이 사라질 수 있다. 따라서 운영 삭제·migration·API 배포를 하지 않았다. 현재 실행기는 이 조건을 감지하면 원본 삭제 전에 멈추고 차단 상태를 유지한다.

- [x] 동일 DB 버전의 압축 청크·동시 수신·서명 응답 시험 및 실제 `sss` 사본 파기.
