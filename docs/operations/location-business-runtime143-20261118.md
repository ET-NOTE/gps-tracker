## 결과와 범위

회사 자료 검토 항목을 추가할 때 기존에는 연결 단서 첫50개만 표시하고 이후에는 번호를 직접 입력해야 했다. 이제 **현재·과거 회사/명단 연결을50건씩 탐색하고 회사명·번호·연결 상태로 검색해 선택**할 수 있다.

- ‘회사·명단 연결 찾기’를 열 때만 조회한다. 회사명은 대소문자를 무시하는 일반 문자열 검색이며 `%`·`_`도 그대로 찾는다. 회사 계정 번호·명단 번호는 정확히 일치시킨다.
- 전체/현재 연결/연결 해제 이력과 이전/다음/처음·새로고침, 조회 취소를 제공한다. 검색 조건 변경은 첫 페이지로 돌아가고 실제 다음 행이 있을 때만 다음 버튼을 켠다.
- 회사명·회사/명단 번호·현재 연결 여부·최초/마지막 관측 시각만 보여준다. 관측 시각은 실제 소속 시작/종료일이 아니고, 회사명은 현재 회사 정보 기준이다. 연결 단서는 본인 확인·제공 권한이 아니다.
- 선택한 과거 연결을 검색창을 다시 열어도 유지한다. 별도 확인한 번호의 수동 입력은 남긴다. 요청 또는 리비전이 바뀌면 이전 선택을 초기화한다.
- 조회 중/오류/취소에는 오래된 선택 버튼을 숨기고 HTTP 요청을 중단한다. 검색 Enter는 검토 항목 추가를 실행하지 않는다. 추가 중에는 선택·검색을 잠그며 승인/리비전 오류를 표시한다.
- 기존 candidates GET 경로에 선택 query(`after_owner`+`after_staff`, `linked`, `q`)와 `next`를 추가했다. 기존 `items`·`more`·`identity_confirmed:false`는 유지한다. 복합 커서와 검색어80자 제한을 검증한다. 별도 경로/스키마 변경은 없다.
- 검토 항목 추가는 기존 승인·리비전·회사/명단 검증을 거친다. 검색/선택만으로 본인 확인·회사 요청 발행·자료 제공을 처리하지 않는다. 과거 단서의 현재 명단 소속이 바뀌었어도 기존 역사적 연결 검사로 항목을 추가할 수 있으나 결과는 **본인 범위 확인 전**이다.

**구현·기능 검증 완료, 운영/dev 미배포**다. 스키마114·기존 정책·APK/펌웨어를 유지하고 부하 검증을 확대하지 않았다. 운영 서버와 동료의 dev-gps 작업에 접속/변경하지 않았다. 마지막 확인 배포는 API `review137-20261116-r3`, 웹 `android139-web-20261118-r1`, Android1.0.8(14)이며140~143차는 후보 상태다.
