## 구현

- `GET /privacy/requests/:id/history`: 인증 계정의 요청만 조회한다. 타인/없는 요청은404, 익명/이용 종료 계정의 세션은401이다. 관리자도 이 개인 경로로 타인 요청을 조회할 수 없고 회사 위임 헤더도 거부한다. 기존 관리자 상세 경로와 권한은 유지한다.
- 공개 응답: 요청 번호, 기준/현재 revision, 다음 위치와 이력의 revision·상태·공개 안내·당시 처리 기한·시각만 반환한다. 담당자/계정ID, 내부 증빙번호, 계정 종료 작업 정보는 포함하지 않는다. 공개 안내문은 기존 ‘사용자에게 전달할 안내’ 필드이며 내부 메모를 자동 공개하지 않는다.
- 최신순25건, 한 SQL에서 소유자·현재 revision·공개 이력을 읽는다. `through` 기준을 다음/이전 페이지에 유지해 새로 추가된 이력이 섞이지 않게 하고 새 처리가 있으면 새로고침을 안내한다. 양수 integer 커서만 허용하고 알 수 없는 필드를 거부한다. 과거 이력이 없는 자료를 임의로 생성하지 않는다.
- 읽기 전용 트랜잭션·기존2개/20초 조회 보호·연결 취소·`no-store, private`를 적용한다. 정상 빈 조회는 트랜잭션을 끝낸 뒤404를 반환하므로 불필요한 취소 정리가 슬롯을 붙잡지 않는다. 첫 후보에서 발견된 문제와 수정 결과를 모두 보존했다.
- 개인 요청 카드의 ‘처리 이력 보기’를 누르면 조회한다. 접기·취소·화면 종료 시 중단하고 늦은 응답을 버린다. 비활성 캐시는 남기지 않으며 페이지 이동/실패 중 옛 행을 보여주지 않는다. 공개 안내는 React 텍스트로 렌더링한다. 요청 revision 변경 시 이력 화면을 새로 시작한다.
