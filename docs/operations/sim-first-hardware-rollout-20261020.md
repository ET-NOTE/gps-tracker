# SIM 기준 등록과 하드웨어 인증 분리

2026-10-20 KST. gps.serial.kr 운영 반영. dev-gps에는 배포하지 않았다.

## 사용자 절차

1. 개별 인증정보가 준비된 운영 펌웨어의 단말기에 SIM을 넣고 전원을 켠다.
2. LTE 연결 뒤 **단말기 → 추가**에서 1NCE 화면의 ICCID 끝 8자리와 이름을 입력한다. 처음 등록하는 SIM도 동일하다. SIM 인쇄 번호의 끝 8자리 또는 전체 번호(19~20자리)도 허용한다. 등록번호나 시리얼 명령은 요구하지 않는다.
3. 처음 등록·신규 하드웨어 연결·본인 계정 조회 모두 끝 8자리로 가능하다. 1NCE의 19자리 표기와 모뎀의 20자리 표기의 끝번호를 모두 조회하며 후보가 중복되면 전체 번호를 입력한다.
4. 같은 계정에서 승인된 하드웨어끼리 SIM을 옮기면 기존 SIM의 장치 ID와 기록에 이어서 수신한다. 새 하드웨어의 최초 연결도 SIM 끝 8자리로 승인한다.
5. **데이터 보관 후 해제**한 SIM은 같은 계정에서 다시 연결하면 예전 기록이 복원된다. 하드웨어가 달라도 된다. 다른 계정에 넘기면 이전 계정 기록은 새 계정에 공개되지 않는다.

SIM은 기록의 기준이고, 하드웨어 인증키는 실제 송신 단말기의 기준이다. 사용자가 인증키를 입력하거나 복사하지 않는다. 제조·운영 단계에서 각 하드웨어에 고유 키를 준비해야 하며 임의의 미인증 펌웨어가 SIM만 입력해 통신하는 구조는 아니다.

## 데이터 및 인증 규칙

- `devices.id`는 SIM의 논리 ID이며 계정·기록·통계 기준을 유지한다. 기존 행을 새 하드웨어 UID로 교체하거나 기록을 다른 장치 행으로 옮기지 않는다.
- `hardware_credentials.auth_uid`는 물리 하드웨어의 서명 ID다. 키 digest·증가 카운터·승인 계정·현재 SIM을 별도로 저장한다. V2 요청 본문은 실제 설치된 SIM을 전달하며 NVS의 서명 ID로 덮어쓰지 않는다.
- 1NCE의 19/20자리 표현은 정규화해 하나의 SIM으로 처리한다. 짧은 번호는 기존 소유자의 모호하지 않은 조회에만 사용한다.
- 최초 등록은 모호하지 않은 SIM 끝번호(8자리 이상)와 최근 5분 내 서명 검증에 성공한 해당 SIM의 접속, 소유권 재검사와 계정별 10분당 10회 제한을 적용한다. 연결 해제 전 접속은 재사용하지 않는다. 후보가 여러 개면 임의로 고르지 않는다.
- 기존 소유자가 이미 승인한 하드웨어가 여러 개여도 SIM 재조회는 정상 처리한다. 미승인 새 하드웨어가 있으면 그 후보를 먼저 승인한다.
- 같은 계정 하드웨어의 SIM 교체는 자동 수신한다. 다른 계정 소유 SIM으로 임의 전송하면 기록을 쓰거나 소유권을 넘기지 않는다.
- 최초 V2 전송이 성공한 SIM은 unsigned fallback을 영구 차단한다. 연결 해제해도 이 플래그를 되돌리지 않는다.
- 하드웨어·SIM advisory lock 뒤 기존 ingest를 실행하고, ingest 트랜잭션이 끝난 뒤 하드웨어의 FK 연결을 게시한다. FK 잠금과 별도 ingest 연결 사이의 교착을 방지한다.

ICCID와 끝번호는 비밀키가 아니다. 사용자가 요청한 SIM 입력 중심의 최초 등록은 별도 소유 증명 코드 없이 수행한다. 최근 인증 접속·미소유 여부·시도 제한이 있지만, SIM 번호나 끝번호만으로 물리적 SIM 점유를 암호학적으로 증명한다고 설명하면 안 된다.

전송은 기존 modem HTTP에 요청·응답 HMAC과 증가 카운터를 적용한다. TLS 암호화가 아니며 좌표 기밀성을 제공하지 않는다. 전환 전 구버전 하드웨어의 허용 범위는 별도 유지한다.
