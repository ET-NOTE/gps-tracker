## 재현한 문제와 변경

1. SDK가 차량 목록보다 먼저 준비되면 빈 지도에서 최초 위치 맞춤을 소비했다. 실제 유효 위치가 생긴 뒤 한 번만 맞추며, 첫 WS 위치가 SDK보다 먼저 도착해도 보존한다. 이후 폴링 때 사용자의 지도 시점을 계속 초기화하지 않는다.
2. 연결 해제된 차량을 목록에서만 제거하고 지도 마커는 남겼다. 현재 소유 목록에서 사라진 차량의 마커를 제거하고, 늦은 WS 메시지로 복원되지 않도록 검사한다. 이 검증은 모의 데이터로 수행했으며 운영 차량을 삭제하거나 연결 해제하지 않았다.
3. 최신 WS 위치가 오래된 REST 스냅샷으로 되돌아갈 수 있었다. 시각·좌표 검증을 거쳐 최신 위치만 채택하고, 변하지 않은 마커는 다시 그리지 않는다. 시각이 없는 스냅샷은 최초 유효 fix를 막지 않도록 표시하지 않는다.
4. Fleet은 재연결의 resync를 무시했다. 재연결 시 차량 스냅샷과 선택한 차량의 이벤트를 재조회한다. 연결 중단 안내는 30초 폴링과 실시간 연결을 구분한다.
5. 이벤트 조회 실패를 빈 배열로 바꿔 ‘최근 이벤트 없음’으로 표시했다. 오류·진짜 빈 결과를 구분하고, 같은 차량에서 마지막으로 성공한 기록은 유지하면서 재시도를 제공한다. 차량 전환 후 이전 응답이 새 차량의 이벤트를 덮지 못한다.
6. 운행 경로 실패를 콘솔에만 기록하고, 이전 경로가 남을 수 있었다. 새 조회 전에 이전 경로를 지우며 로딩·실패·좌표 없음·재시도를 표시한다. 선택 변경·취소·지도 재생성·언마운트 후 도착한 이전 응답은 적용하지 않는다. canvas URL도 Router의 현재 query를 따른다.
7. 지도와 운행 상세가 같은 좌표를 두 번 요청했다. 승인된 한 결과를 지도와 상세에 함께 전달한다. 운행 이력 목록 조회에도 사용자용 오류 안내와 재시도를 추가했다.
8. 위치가 없는 차량을 선택했을 때 비어 보이는 지도에 최근 위치 미수신 안내를 추가했다. 통신 상태와 위치 수신을 구분하며, 과거 운행 경로를 보는 동안에는 이 안내로 경로를 오해하지 않게 한다.
