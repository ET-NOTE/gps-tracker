# 113차 — 중단된 일간 집계의 누락 날짜 복구

2026-11-11. **구현·격리 검증 완료, 운영 미배포. DB 스키마는112 유지**다. 인프라의 `security113/114`와는 별개인 GPS 애플리케이션 작업이다. 백신·WAF 실무 검증은 사용자 요청대로 계속 보류한다.

## 문제와 변경

112차에서 확인한 기존 catch-up은 현재 소유자의 `daily_stats`가 **한 행도 없는 장치**만 처리했다. 집계 중 종료되거나 일부 날짜만 가져온 장치는 이미3일이 있으면 나머지28일이 자동 복구되지 않았다. 날짜 조회 실패도 빈 목록으로 삼켜졌다.

수정한 워커는 소유 장치를 ID 순서로 순환하며, 현재 소유자의 원본에서 **없는 날짜만** `stats_rebuild_queue`에 먼저 저장한다. 기록 일부가 이미 있어도 복구한다. 대기열 커밋 뒤에만 탐색 커서를 이동하므로 프로세스 종료 시에도 이미 발견한 작업은 남는다. 재시작하면 탐색 커서부터 다시 찾지만 대기열 충돌은 무시하므로 작업을 잃거나 기존 재시도 상태를 덮어쓰지 않는다.

- 한 번에 최대10장치, 장치당 원본1000행. 커서는 `(recorded_at, source)`로 같은 시각의 다른 소스를 보존한다. 배치 내부 시각의 **KST 날짜**를 계산한다.
- 날짜 탐색은 장치 잠금1초·쿼리10초 제한을 둔다. 한 장치가 중지·잠금·오류 상태여도 다음 장치를 탐색한다. 원본 페이지 안에서 발견한 날짜만 복구하며 빈 날짜를 임의로 채우지 않는다.
- 기존 작업의 `generation`, 실패 횟수, 재시도 시각을 유지한다. 작업 중 새 무효화가 발생하면 이전 세대의 완료 처리가 새 작업을 지우지 않는다.
- 이용 중지/정보주체 경계는 기존 privacy lease를 탐색과 계산 모두에 적용한다. 수집만 중지한 경우에는 기존 정책대로 과거 기록의 집계 복구는 가능하며 새 위치 수집은 계속 차단한다.
- 현재 소유자의 원본만 집계한다. 소유자가 바뀌면 원본 탐색 커서를 초기화한다. 연결이 해제된 장치에 새 무소유0값 통계를 만들지 않는다.
- SIM 기반 논리 장치의 ID를 그대로 사용한다. 하드웨어 UUID, SIM 소유, 동의, 원본 및 암호화 방식, 거리·속도 계산식을 변경하지 않는다.

탐색 커서는 메모리에 있고 대기열은 DB에 있다. 매우 잦은 재시작은 아직 발견하지 못한 오래된 페이지의 탐색을 늦출 수 있다. 새로운 원본이 커서 이전 시각에 추가되면 수신 경로의 무효화 대기열 또는 다음 전체 순환에서 처리한다. 이미 존재하지만 잘못된 통계 전체를 검사하는 기능은 아니며, 그 재계산은 기존 무효화 대기열을 따른다.
