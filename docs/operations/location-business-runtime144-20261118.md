## 결과와 범위

회사 자료 검토 대장의 변경 이력이 최근100건에서 끊기던 부분을 보완했다. 이제 **50건씩 과거 이력을 탐색하고 당시 검토 상태·검토 항목으로 필터링**한다.142차의 회사 제출·증빙 행위 이력과 구분되는 관리자의 검토 판정 기록이다.

- ‘검토 변경 이력 보기’를 열 때만 조회한다. 이전/다음/처음·새로고침·취소를 제공한다. 닫기/다른 상위 요청/리비전 변경 시 과거 결과와 진행 중 요청을 제거한다.
- 당시 상태7종·해당 요청의 검토 항목으로 필터링한다. 조건 변경은 첫 페이지로 돌아가고 실제 다음 행이 있을 때만 다음 버튼을 켠다. 오류/취소/조회 중에는 기존 행을 숨기며 빈 목록과 실패를 구분한다.
- 이력ID·검토ID·버전·수행 계정·기록 시각, 당시 본인 판정·검토 상태를 표시한다. 상세에서 당시 자료 종류·기간·기한·기록된 처리 결과·내부 사유·본인 확인 근거·처리 근거·요청자 안내를 읽는다. 긴 참조번호는 모바일에서 줄바꿈하고 문자열을 HTML로 실행하지 않는다.
- 현재 검토 상태를 과거 기록에 덮어쓰지 않는다. 기록 조회는 실제 자료 정정/파기/전달 완료나 새로운 승인·실행이 아니며 이를 화면에 명시했다. 회사 제출·증빙 이력은 기존 각 검토 항목에서 조회한다.
- 새 GET `/admin/privacy/requests/:id/company-review-events`는 `before`, `review_id`, `status`를 받는다. 잘못된/알 수 없는 조건은400, 없는 상위 요청은404, 해당 요청 밖의 검토 번호는 빈 목록이다.6개 이력 필드와11개 당시 상태 필드만 명시적으로 반환하고 원시 state/회사 inventory/임의 추가 필드는 제외한다.
- 기존 관리자 TOTP·IP·역할·세션 및 접근/응답 감사 검사와 조회 예산·SQL 취소를 적용한다. 기존 회사 검토 API의 `items`와 최근100 `events`, 본인용 공개 요약을 유지한다. 스키마 변경은 없다.
