# 위치정보사업 준비 · 8차: 회사 자료 검토와 처리 근거

작업일: 2026-11-05. 분기: `codex/location-business-prep`.

## 이번 범위

관리자 → 개인정보 요청 → 해당 요청에 **회사 자료 검토 대장**을 추가했다. 계정 이용 종료를 시작한 요청에서도 회사 자료 검토를 계속할 수 있다.

회사 계정·직원 명단·자료 종류·기간별로 항목을 만들고 본인 범위 판정, 확인 근거, 내부 검토 사유, 공개 안내, 기한, 처리 근거를 기록한다. 대상은 직원 명단, 운행 기록, 예약, 지출, 첨부자료, 이름 스냅샷 등이다. 직원이 회사에 남긴 개인정보를 검토하는 절차이며 회사 소유자 자신의 전체 사업자료 삭제 절차를 대체하지 않는다.

회사 자료의 조회·추출·정정·삭제를 이 화면에서 실행하지 않는다. 실제 자료 전달이나 정정·파기는 기존 도구와 확인된 절차로 수행하고, 담당자가 결과를 확인한 뒤 참조번호를 연결한다. **‘담당자 처리 확인’은 담당자의 증빙 확인이며 시스템이 원본 삭제·전달 성공을 자동 검증했다는 뜻이 아니다.** 회사에 자동 문의·메일·알림도 보내지 않는다.

## 연결 이력과 정보주체 경계

- `privacy_company_link_history`는 회원 계정과 회사 직원 명단의 현재 연결을 이관하고, 이후 연결·연결 해제의 계정/회사/명단 번호 및 시각만 남긴다. 이름·연락처·좌표는 복사하지 않는다.
- 이용 종료로 `fleet_staff_accounts`가 삭제돼도 최소 연결 이력이 남는다. 이 이력은 본인 범위 확인의 단서일 뿐 회사 조회 권한을 복구하지 않는다. 동일 명단을 다른 직원에게 재배정했거나 스냅샷에 과거 이름이 남았을 수 있으므로 자동 본인 판정은 하지 않는다.
- 마이그레이션 전에 연결이 삭제된 직원과 로그인 계정에 연결되지 않았던 명단은 소급 복구할 수 없다. 별도 증빙으로 회사·명단을 지정하고 확인한다. 이름만으로 매칭하거나 과거 NULL 소유자 자료를 귀속시키지 않는다.
- 회사 업무 자료의 소유자와 자료에 등장하는 사람은 별개다. 회사 전체 자료를 직원에게 제공하지 않는다. **SIM 논리 장치, 수신 당시 계정, 차량 배정 경계와 단말 인증 구조는 변경하지 않았다.**
- 연결 이력과 처리 대장 역시 개인정보일 수 있다. 익명자료나 영구 보존 자료로 간주하지 않는다. 보관 기간·근거·파기 정책은 아직 회사 확정이 필요한 열린 항목이다.

## 검토 흐름과 보호

1. 회사·명단 연결 단서 또는 별도로 확인한 범위를 지정한다. 자료 종류와 최대 366일의 기간, 검토 기한을 입력한다. 요청당 최대 50개 항목이며 더 넓은 범위는 분할한다.
2. 등록 시점의 명단별 운행·예약·지출 후보 건수를 기록한다. 각각 1만 건까지만 표시하고 초과는 `more`로 구분한다. 운행은 시작 시각, 예약은 기간 겹침, 지출은 한국 날짜를 기준으로 한다. 첨부·이름 스냅샷·명단 없는 기록은 별도 점검한다. 후보 건수가 전체 개인정보 목록이나 본인 자료 확정 건수는 아니다.
3. 본인 범위를 확인한 근거가 있어야 ‘검토 중·회사 확인 대기·보관/처리 기준 검토’로 이동한다. 처리 확인·제외·제한은 근거 참조번호, 사유, 공개 안내와 담당자 확인을 요구한다.
4. 열람은 전달 확인, 정정은 반영 확인, 삭제·탈퇴 관련 항목은 해당 범위 파기 확인으로 결과를 구분한다. ‘제외’는 본인 자료가 아니라는 근거, ‘제한’은 본인 범위와 제한 근거를 요구한다.
5. 미해결 항목이나 제한 항목이 있으면 전체 요청의 ‘처리 완료’를 차단한다. 미해결 항목이 있으면 전체 반려도 차단한다. 회사 항목을 모두 확인해도 **탈퇴·전체 삭제 완료 차단은 그대로 유지**한다. 기존 회사 연결 검토 사유도 자동 해제하지 않는다.

플랫폼 관리자만 대장에 접근한다. 회사 관리자 역할이나 `X-Fleet-Owner` 위임으로 접근할 수 없다. 요청/항목 revision과 부모 요청 행 잠금으로 동시 수정을 직렬화한다. 대상·기간·초기 후보 목록은 수정할 수 없고 새 범위로 등록해야 한다. DB에서도 범위 변경과 미해결 전체 완료를 막는다.

변경은 `privacy_company_review_events`에 추가되며 API에 이력 수정·삭제 기능은 없다. 원본 자료 대신 내부 문서 참조번호를 기록한다. 이 기능을 DB 최고 권한까지 막는 변조 방지 감사 저장소라고 주장하지 않는다.

요청자는 로그인 후 본인 요청 또는 `/privacy/result` 결과 전용 화면에서 자료 종류·기간·상태·공개 안내·기한만 본다. 회사/명단 번호, 후보 건수, 본인 확인 증빙, 내부 사유, 담당자 정보는 노출하지 않는다. 결과 응답은 `no-store, private`이며 계정 종료 후 일반 로그인은 계속 차단된다.
