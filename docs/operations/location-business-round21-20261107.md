# 21차 — 수집·이용·제공 중지와 보관·파기

2026-11-07. `codex/location-business-prep` / PR #248. **개발 후보 스키마 105, 운영 미배포**. 이 문서의 시험은 내부 Docker 네트워크·tmpfs DB·합성 계정으로 수행했다. 운영 사용자 데이터, SIM 소유권, 단말기 펌웨어, 서비스·방화벽·키 설정은 변경하지 않았다.

## 동작

### 세 가지 중지

- **수집:** 기존 SIM별 `/privacy/collection`과 단말 정책 epoch/ACK를 유지한다. 서버 저장 차단은 즉시, 단말 설정은 다음 통신에 적용된다. 재개는 새 epoch의 ACK 이후다. 이번에는 실물·실외 버퍼 시험을 재실행하지 않았다.
- **이용:** 새 `/privacy/processing`에서 계정 단위로 중지한다. 위치 조회·운행 리포트·자동 분석·통계·펜스/지점 계산 경로를 차단한다. 수집 허용과 독립적이므로 이용만 중지하면 원본 수집은 계속될 수 있다.
- **제공:** 본인 조회를 유지하면서 공유 링크·회사 범위 조회·외부 처리 전송을 차단한다. 외부 지도 주소 변환도 제공 경계를 통과해야 하므로 중지 중에는 주소가 표시되지 않을 수 있다.
- 본인 정보의 열람·삭제 요청과 검토된 권리 대응은 중지 중에도 사용할 수 있다. 이미 제공된 파일·이미 전달된 네트워크 바이트를 회수하는 기능은 아니다.

조회 기록 설정이 OFF여도 중지 제한은 작동한다. HTTP 응답 준비, 외부 전송, 실시간 메시지의 공통 진입점에 DB 공유 잠금을 유지한다. 중지 변경은 배타 잠금을 즉시 얻을 때만 확정한다. 처리 중이면 **409, 변경 없음**으로 응답하며 재시도를 안내한다. 오래 열린 응답의 이미 준비된 본문·실제 단말 수신 시점까지 취소됐다고 주장하지 않는다.

두 토글은 revision으로 동시 수정을 검사한다. 변경과 이력을 같은 트랜잭션에 저장하고 대기 중인 위치 관련 FCM을 취소한다. 차단 시 423, DB 오류·미분류 경로는 실패 시 차단한다. 웹은 성공한 변경 후 조회 캐시와 로컬 위치 캐시를 비우며, 먼저 시작한 요청이 캐시를 다시 채우는 것도 막는다. 다른 브라우저·내려받은 외부 사본을 원격 삭제하지는 않는다.

**회사 범위:** 실제 운전자 귀속을 현재 SIM 소유자로 대신하지 않는다. 회사 소유자 또는 연결 직원이 제한하면 혼합된 회사 위치 응답을 보수적으로 보류한다. 관계없는 회사 전체를 막지는 않는다. 관리자 전체 조회/귀속 불명 처리에는 제한 계정의 자료가 섞일 가능성이 있어 응답 전체가 보류될 수 있다. 직원 연결이 해제된 과거 운전자·시간대별 동의의 확정은 22차 정보주체 매핑의 인수 조건이다.

잠금은 계정별이 아닌 GPS DB 전체의 공통 잠금이며 별도 연결 풀 상한은16개다. 트래픽이 많은 동안 중지 변경이409로 반복될 수 있다. 운영 활성화 전에 실제 동시 조회·외부 처리 시간·DB 연결 예산을 반영한 부하 리허설이 필요하다. 격리 시험 통과를 운영 처리량 보장으로 해석하지 않는다.

### 보관 엔진

`ops/privacy_retention.py`는 기본 **dry-run**이다. 실행에는 별도 정책 ON, 근거 식별자, 계정별 명시적 보관 동의가 모두 필요하다. 기존 계정에 동의를 소급 생성하지 않는다.

| 규칙 | 구현 |
|---|---|
| 일반 기간 | 명시적 1~6개월. 요구 기준은 6개월이며 달력 월 단위로 계산 |
| 연장 기간 | 최대 12개월, 계약 종료일 필수. 계약 만료 시 해당 동의로 보유하던 처리 대상 기록을 정리 |
| 무동의 계정 | 삭제·기간 추정 없이 유지, 등록된 동의가 없다고 화면 표시 |
| 회사 계정/직원 | 회사 자료 귀속과 보관 근거를 별도 검토하도록 자동 파기 보류 |
| SIM 이동 | `location_records.user_id` 등 당시 계정 범위로 삭제. 현재 소유자로 과거 행을 재귀속하지 않음 |
| 실패 | 계정 단위 트랜잭션 취소. 앞서 성공한 다른 계정은 유지되므로 전체 작업의 원자성으로 해석하지 않음 |

처리 범위는 `location_records`, `events`, `daily_stats`, `ai_analyses`, `fcm_outbox`의 계정 귀속 행과 해당 소유자의 만료된 최근 위치 캐시다. 일별 파생 통계/분석은 경계 날짜 전체를 정리할 수 있다. 새 소유자의 최근 위치·다른 계정의 과거 행은 보존한다. 주소 캐시는 계정 귀속이 없으므로 DB 캐시를 비우고, 암호화 또는 보관 정책이 ON인 서비스는 주소의 DB/프로세스 캐시를 사용하지 않는다. 같은 요청 안의 중복 좌표 정리는 유지하지만 외부 주소 API 호출량은 늘 수 있다.

`covered_rows_erased=true`는 **위 표의 처리 대상 행만 검사한 결과**다. 모든 개인정보·외부 사본의 완전 삭제 증명이 아니다. 회사 차량 문서, 지출·회계 원본, 개인 파일, 감사/취급대장, 구 백업·WAL·스냅샷은 별도 정책/기존 권리 처리 경로에 남는다. 계정 귀속이 NULL인 원본·소유자 열이 없는 구 집계도 자동 삭제하지 않는다. 구 집계는 파기 대상 SIM의 경계 이전 구간을 논리 읽기 뷰에서 보류하고 물리 원본은 귀속 검토 대상으로 남긴다.

파기 확정 시 계정·시각 경계와 대상 SIM 목록을 기록한다. 동일 경계보다 오래된 원본 재삽입과 파생 재생성을 차단한다. **시각은 저장된 수신 행의 `recorded_at` 기준**이며, 단말기가 재전송한 모든 개별 GPS 측정 UTC를 새로 인증하는 기능이 아니다. 단말 버퍼의 수집 중지 경계는 기존 epoch/ACK 규칙에 의존한다.

### 복원 후 재등장 방지

`ops/privacy_restore_checkpoint.py`는 현재 중지·보관 동의·파기 경계·SIM 수집/계정 차단 상태를 별도 600 파일로 내보낸다. 키·좌표는 포함하지 않지만 식별자가 있으므로 비공개 보관해야 한다.

1. 최신 checkpoint와 SHA-256을 DB 백업과 독립된 관리 장소에 보관한다. SHA는 무결성 대조이며 전자서명·최신성 증명이 아니다. 운영자가 신뢰할 수 있는 최신 사본을 확보해야 한다.
2. 복원 서버는 외부 개방 전에 API·워커·모든 DB 클라이언트를 멈춘다. 스크립트는 다른 DB 연결이 남으면 거부한다. 이 검사는 접속 차단 설정 자체를 대신하지 않는다.
3. 해시, 계정 생성 시각, SIM 식별자/소유권을 검증한다. 소유권이 다르면 자동으로 덮어쓰지 않고 오프라인 정합 작업을 요구한다.
4. 최신 중지와 삭제 경계를 재적용하고 해당 경계 이전 데이터를 다시 삭제한다. SIM에는 새 epoch를 부여해 복원 전 ACK를 재사용하지 않는다. 지원 펌웨어의 새 ACK 전까지 수집 재개가 지연될 수 있다.
5. 결과를 검토하고 기존 계정 종료/검토된 파기 작업의 결과도 별도 재검증한 뒤 서비스한다. checkpoint는 과거의 모든 종류의 파기와 외부 백업 제거를 대체하지 않는다.

운영 외부 checkpoint 저장소·주기·접근권한·이전 사본 파기와 복원 담당자는 아직 정해지지 않았다. 따라서 현재 후보를 **백업까지 자동 완전 파기 완료**라고 제출하지 않는다.

## DB 권한과 실행

API runtime은 중지 상태를 처리할 업무 권한만 추가한다. 보관 정책/동의/파기 경계는 읽기만 가능하고 변경·삭제와 트리거 변경은 거부된다. schema owner/검토된 유지보수 경로에서만 정책과 동의를 설정한다. 전용 정리 OS 계정의 환경·키 접근권한·DB 유지보수 권한을 확정한 뒤 서비스 예제를 설치한다. 일반 API 계정에 schema owner 비밀번호를 넣지 않는다.

`ops/gps-privacy-retention.service.example` / `.timer.example`는 시간당 실행 후보이며 **설치·활성화하지 않았다**. `privacy_retention_policy.enabled`는 파기 허용 여부이며 타이머의 실제 건강 상태를 증명하지 않는다. 실행 실패·동의 누락·회사 보류·checkpoint 지연의 운영 경보는 인수 때 연결해야 한다.
