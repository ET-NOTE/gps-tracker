# 위치정보사업 준비 — 9차 계정 정보·개인 서류 열람 제공

작성: 2026-11-05. 브랜치 `codex/location-business-prep`.

## 이번 범위

개인 위치 CSV에 이어 **현재 계정 기본정보, 개인정보 요청과 공개 처리이력, 검토한 개인 서류**를 제공한다. 회사 자료·거래·설정·사진 등까지 포함한 전체 개인정보 제공이나 법적 의무 충족 완료를 선언하지 않는다. 기존 SIM 논리 장치, 수신 당시 계정 귀속, 인증 펌웨어와 수집 정책은 변경하지 않았다.

관리자는 개인정보 열람 요청을 검토 상태로 전환하고 기한을 지정한 뒤 ‘계정 정보·개인 서류 제공’에서 발급한다. 요청자는 기존 개인정보 요청 내역에서 현재 비밀번호를 다시 입력하고 JSON 또는 개별 서류를 내려받는다. 기존 웹을 사용하는 앱에도 적용되며 APK·펌웨어는 이번에 변경하지 않았다.

## 제공 내용과 경계

| 범위 | 이번 제공 | 별도 확인 범위 |
|---|---|---|
| 계정 | 이메일, 표시 이름, 기본·보조 연락처, 기본 연락처 확인 여부, 가입/수정 시각 | 추가 전화번호 목록, 설정, 구독·포인트·거래, 채팅·AI 등 |
| 처리이력 | 본인의 개인정보 요청 종류·범위·상태·공개 안내·기한·시각과 공개 상태 변경 안내 | 운영자 내부 증빙·사유, 접속·수집·이용·제공사실 전체 대장 |
| 개인 서류 | 관리자가 내려받아 검토하고 선택한 개인 장치 서류 원본과 목록 | 회사 차량 서류, 회사 연결 이력이 있는 장치, 공동 파일, 소유권 변경 장치, 차량 사진, 계약 사진·영수증 |
| 위치 기록 | 기존 7차 CSV 제공을 계속 사용 | 회사 자료·소유자 불명 기록 등은 기존 별도 검토 유지 |

JSON에는 `coverage`, `excluded`, 생성 시각, 명시적인 부분 제공 안내가 들어간다. 다운로드 당시 남아 있는 기본정보와 요청 이력을 조회한다. 비밀번호 해시, 인증·API 키, 서버 저장 경로, 원본 설정 JSON, 담당자 내부 증빙을 통째로 내보내지 않는다. 기본 연락처와 보조 연락처만 제공하며 추가 전화번호 목록까지 포함했다고 표시하지 않는다.

처리이력은 요청 200건·공개 이벤트 2,000건을 넘으면 오류로 중단하고 분할 제공을 요청한다. 조용히 잘라 전체 자료처럼 제공하지 않는다. 회사 검토 대장의 결과는 기존 화면에서 확인하며 이번 JSON의 처리이력 범위는 개인정보 요청의 공개 이벤트다.

## 개인 서류의 검토와 파일 보호

1. `device_documents.user_id`가 요청자이고 현재 장치도 본인 소유여야 후보가 된다. 회사 차량 서류·회사 장치 연결 이력·삭제 차단 대상·동일 경로의 공동 참조는 제외한다. 이 조건은 자동 제공의 보수적인 경계이며 제외 자료에 대한 정보주체 권리를 부정하는 판정이 아니다. 별도 검토한다.
2. 담당자가 후보 원본을 내려받은 기록과 SHA-256이 있어야 발급에 포함할 수 있다. 같은 담당자가 최근 24시간 안에 받은 파일의 해시와 발급 시 실제 파일의 해시를 대조한다. 화면에서 내용과 타인 정보 포함 여부를 확인하는 명시적 확인도 필요하다. 응답을 받은 사실만으로 사람의 검토가 자동 검증되는 것은 아니다.
3. 발급은 최대 20개, 파일당 10MB다. 파일의 내용, 이름, MIME, 소유권·회사 연결·공유 참조·삭제 차단이 바뀌면 다운로드를 거절한다. 다른 계정과 과거 업로더의 서류를 현재 SIM 소유자에게 자동 제공하지 않는다.
4. `UPLOAD_DIR/device_documents/<요청자>/<논리 장치>/<서버 파일명>`만 읽는다. Linux에서 각 경로 요소를 `openat/O_NOFOLLOW`로 열고 일반 파일·하드링크 수·크기를 확인한다. 심볼릭 링크, 하드링크, 루트 밖 경로, 비정상 크기를 거절한다. 지원하지 않는 운영체제에서는 파일 제공을 거절한다.
5. 응답은 `attachment`, `application/octet-stream`, `nosniff`, `no-store, private`다. 원래 파일명은 검토 목록에만 표시하고 다운로드 이름은 고정 형식으로 만든다. 관리자 검토 응답의 해시 헤더는 허용된 교차 출처 앱에서도 읽을 수 있도록 노출한다.

범위와 삭제 작업의 동시 변경을 막기 위해 요청·계정·발급 잠금과 첨부/장치 연결 테이블 잠금을 사용한다. 파일 읽기는 크기 제한을 두고 별도 blocking 작업에서 수행한다. 대용량 파일 전체를 DB에 복제하거나 미리 생성한 압축 파일을 공개 경로에 남기지 않는다.

## 발급·접근 통제

- 플랫폼 관리자만 후보 확인·검토·발급·회수한다. 회사 위임 권한으로 사용할 수 없다.
- 요청 revision 충돌을 차단한다. 재발급하면 같은 요청의 이전 계정 자료 발급을 회수한다. 위치 CSV 발급은 별도로 유지한다.
- 유효 기간은 24시간이다. 본인 활성 계정 세션과 현재 비밀번호가 모두 필요하고, 기존 위치 제공과 비밀번호 재확인 시도 제한을 공유한다.
- 회수·만료·요청 취소·반려·계정 이용 종료 후에는 다운로드할 수 없다. 결과 전용 조회가 일반 로그인이나 자료 접근을 되살리지 않는다. 종료 계정에 실제 자료를 전달하는 별도 본인 확인 경로는 열린 항목이다.
- `privacy_account_packages`, `privacy_account_package_events`에 범위·파일 해시·담당자·응답 생성 이력을 기록한다. 해시는 사용자 기기에 저장됐다는 증명이나 익명화가 아니다. 파일 이름과 처리 대장도 개인정보일 수 있어 보관 근거·기간·파기는 후속 정책 확정 대상이다.
- 발급 자체는 요청 전체의 ‘처리 완료’가 아니다. 기존 전체 삭제·탈퇴 완료 차단과 회사 미해결 범위의 완료 차단을 유지한다.
