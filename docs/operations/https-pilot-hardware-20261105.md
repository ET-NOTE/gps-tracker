# HTTPS 파일럿 실기기 검증 — 2026-11-05

대상은 COM62의 ESP32-C3(MAC `68:ee:8f:21:33:64`), SIM 기준 장치 3163(단말-520211)이다.
사용자가 단말기 연결과 검증을 요청했고, 파일럿은 자동 절전·타이머 기상을 비활성화한 상태로 수행한다.
서버 운영 전환이나 다른 단말기의 펌웨어 일괄 갱신은 이번 시험에 포함하지 않는다.

## 보존 및 기준 상태

- 업로드 전 `operating-d541456315`의 HTTP 200 및 서버 저장을 확인했다.
- 4MB 플래시를 접근 제한된 로컬 폴더에 보관했다. 인증정보가 포함되므로 Git이나 배포 ZIP에 넣지 않는다.
- 기존 파티션 테이블이 파일럿과 같음을 확인한 뒤 manifest의 각 바이너리 SHA-256을 검증했다.
- 최초 파일럿 업로드 뒤 NVS `0x9000–0xdfff`를 읽어 업로드 직전과 바이트 단위로 같음을 확인했다.
- 후속 진단 빌드는 app0 `0x10000`만 갱신한다. 전체 삭제·인증키 재발급·SIM 연결 해제를 하지 않는다.
- 기존 하드웨어 서명 ID `sim-47520211`와 SIM 논리 장치 3163을 유지한다. 이 서명 ID의 문자열이 SIM과 비슷해도 인증과 SIM 이력은 별도 구조다.

## 발견과 수정

1. `ae664c1` 상시 기동 파일럿은 LTE 등록과 PDP 활성화에 성공했지만 HTTPS POST 전에 실패했다.
2. 비밀·헤더·위치 본문을 출력하지 않는 TLS 설정 로그와 모뎀 버전 조회를 추가했다.
3. 모뎀은 `1951B12SIM7080`이며 CA 파일의 크기·내용 검증, 변환, TLS 1.2, RTC 검사, SNI, CA 연결 설정을 모두 수락했다.
4. 서버의 제한된 패킷 캡처에서 SNI `gps.serial.kr`, TLS 1.2, `0xC02C` 협상과 이후 모뎀의 연결 종료를 확인했다. 이 사실만으로 서버 인증서 검증 성공을 판정하지 않는다.
5. `AT+CCLK?`는 `80/01/06,00:00:07+00`을 반환했다. 기존 `year >= 26` 검사는 초기화된 GPS epoch 날짜를 정상으로 잘못 인정해 NTP를 건너뛰었다.
6. `11acce8`에서 초기 날짜와 달력 오류·비정상 시각을 거부하고 NTP 결과를 다시 검사하도록 수정했다. 유효기간 검사는 유지한다. Root X2 교체가 필요한 2040년 이후도 이 파일럿에서는 사용 가능한 시계로 간주하지 않는다.
7. 암호군 변경은 원인 분리를 위한 후보였으며 `8925151`은 실기기에 올리지 않았다. 시계 수정 후보는 원래 암호군 선택을 유지한다.

### 후속 개선 — 초기 NTP 응답 처리

두 번의 부팅 모두 첫 동기화 대기는 실패로 판정했으나 다음 시도에서는 시계가 정상화됐다. 아직 원인을 늦은 응답 또는 응답 형식 차이로 확정하지 않는다.
현재 코드는 `+CNTP: 1` 한 줄의 정확한 형식을 기다린다. [SIMCom AT 매뉴얼 V1.07 §16.2.2](https://dfimg.dfrobot.com/60c1e008bddfc41c3293de80/wiki/e8879bae8fcb219d1eeda40686910686.pdf)에는 결과 코드 뒤 시각이 붙을 수 있고 출력 모드도 별도로 설정할 수 있다고 명시되어 있다.
다음 개선에서는 시계 명령의 비밀 없는 원시 응답을 확보해 모드를 명시하고 결과 코드를 해석한 뒤 실제 `CCLK`를 재검사한다. 실패·지연 시에도 유효기간 검사를 끄거나 HTTP로 전환하지 않는다.
