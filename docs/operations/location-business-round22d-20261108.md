# 22D — 미연결 매핑 정정·재동의·외부 제공 경계

2026-11-08. `codex/location-business-prep` / draft PR #248. **운영 미배포, 실제 통보 OFF**. 마지막 문서화된 운영 기준은 18A/schema99다. 이번 후보는 schema108이며 18B~22C 누적 후보 위에서 격리 검증한다. 실제 계정·SIM 소유·운영 VPS·FCM/SMTP 설정은 변경하지 않는다.

## 적용 범위와 동작

- 회사의 운전자 연결 화면에서 기존 요청의 정정 또는 철회 건의 재동의를 요청한다. 요청에는 원래 mapping ID·revision·변경 종류가 들어가며, 같은 요청 번호는 같은 내용만 재실행할 수 있다. 타 회사, 오래된 revision, 이미 후속 요청이 있는 부모는 거부한다.
- 정정은 기존 연결을 `superseded`로 중지하고 새 `pending` 요청을 만드는 하나의 트랜잭션이다. 이전 운전자·차량·SIM·기간·동의 내용·통보 수신자는 수정하지 않는다. 새 운전자가 자신의 계정에서 확인하기 전에는 새 연결을 제공하지 않는다. 잘못된 사람에게 이미 전달된 자료는 이 기능으로 회수되지 않는다.
- 정정은 같은 회사·논리 SIM 범위에서 운전자와 기간/차량 연결을 바로잡는다. 다른 SIM으로 이력을 옮기는 기능이 아니다. 재동의는 철회한 본인·차량 연결·기간을 그대로 유지한다. UI는 재동의 입력을 잠그고 서버에도 원래 시각의 초·소수초를 그대로 보낸다.
- 철회 후 새 일반 요청을 만들거나 다른 사람으로 바꿔 철회를 우회할 수 없다. 명시적인 재동의 요청이 해당 철회 revision에 연결되고 **동일 정보주체가 새로 확인한 경우**에만 해당 기간의 제공을 복구한다. 정정의 여러 후속 단계에서도 이전 철회와 재동의 근거를 검사한다. 다른 사람의 철회 기간과 겹치는 건은 자동 해결하지 않는다.
- 직원 계정 연결 해제 시 그 직원의 pending/confirmed 요청을 중지하고 변경 이력을 남긴다. 같은 계정을 다시 연결해도 과거 동의를 자동 재개하지 않는다. 후속 정정과 본인 확인이 필요하다. 직접 DB에서 연결이 사라진 경우도 유효 매핑 조회에서 제외한다.
- 회사 지도·운행·통계·CSV/XLSX와 기간 제한 위치 조회는 공통 `location_subject_effective` 판정을 사용한다. 기간 밖 위치와 미확인 구간을 표시하지 않는 22B 원칙을 유지한다. 요청마다 현재 직원 연결·역할·차량 배정·중지 상태도 검사한다.
- 정정·철회·직원 권한 변경은 기존 조회의 공유 잠금과 경합하면 409로 재시도를 요청한다. 미완료 응답과 동시에 변경을 성공 처리하지 않는다. 설정 OFF는 과거 매핑이 있는 위치를 이전 비제한 조회로 우회하는 수단이 아니다.

## 외부 제공의 경계

이번 동의의 수신자는 해당 회사의 권한 있는 사용자이고 목적은 차량 운영이다. 이 동의를 공개 링크 방문자·AI·주소 변환 서비스의 동의로 확장하지 않는다.

- 정보주체가 아직 연결되지 않은 회사 SIM도 개인 공유 경로로 빠지지 않는다. 회사 차량 연결 이력이 있거나 매핑 이력이 있는 SIM의 공개 공유 생성·연장은 **포인트 차감 전 409**로 거부한다. 기존 링크의 위치 조회도 차단한다.
- 실제 외부 전송 직전 원장 처리에서 회사/매핑 범위 또는 출처 불명인 processor·공유 요청을 차단한다. 단순히 토큰 생성이나 화면 버튼만 숨기는 방식이 아니다.
- 별도의 개인 계정에 대한 기존 외부 처리 정책은 유지한다. 제공 통보 워커의 위치 없는 알림은 기존 immutable notice 수신자를 사용하며 정정 상대에게 과거 통보를 재배정하지 않는다.
- 외부 수신자별 제공·위탁 여부, 대상 데이터, 목적·기간, 정보주체 동의와 통보 정책이 확정되기 전에는 회사의 공개 공유·외부 AI/역지오코딩 활성화를 지원하지 않는다. 이번 라운드는 그 경계를 **차단 동작으로 구현·검증**한 것이며, 외부 서비스 제공을 승인하거나 법적 충족을 확정한 것이 아니다.

## DB·복원

`0108_subject_revisions.sql`은 replaces_id/replaces_revision/change_kind, 후속 요청 단일성·이전 ID 참조 제약, superseded 상태, 유효 매핑 view, 매핑 identity 변경 거부 trigger를 추가한다. 기존 migration 바이트는 변경하지 않는다. GPS 위치의 SIM 논리 ID, 하드웨어 인증키와 SIM 기록 연속성은 유지한다.

checkpoint는 새 연결 이력을 함께 보존하고, 이전 checkpoint에 필드가 없는 경우 NULL로 해석한다. identity 충돌은 전체 복원을 거부하고 현재 revision보다 오래된 상태로 철회를 되돌리지 않는다. 복원은 발송·제공 정책을 끈 채 끝난다. 운영용 backup custody와 정책 결정은 기존 인수 조건 그대로다.

API 비소유 계정의 schema108 지원, 필드/파일 암호화 전환 도구의 허용 버전을 갱신했다. runtime은 매핑·통보 삭제, 정책 변경, 증빙 수정, trigger 해제 권한을 갖지 않는다. schema108에 새 관계를 쓴 뒤 구버전 바이너리/스키마로 즉시 되돌리는 절차를 제공하지 않는다. 필요 시 최신 checkpoint를 보존한 전진 수정 또는 별도 보호 복원 리허설이 필요하다.
