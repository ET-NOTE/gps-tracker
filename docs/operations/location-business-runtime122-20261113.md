## 현재 운영 판단

운영 RAM은2,967.7MiB, DB 최대 연결50개/관리 예약3개다. 60초 관측에서 다른 프로젝트의 클라이언트 연결이 최대18개였으며 일부 역할에 연결 상한이 없었다. 새 단일 GPS API에28개, 운영 작업에4개를 배정하면 타 프로젝트에 남는15개보다 관측값이 크다. 서비스별 순간 메모리 합계만으로 미래 최대 사용량을 보장할 수도 없다. **현재3GB 공유 서버에 후보를 그대로 전환할 수 있다는 판정은 하지 않는다.**

17:33와17:53KST에 시작한 두 관측에서 스키마99·`privacy-log-20261107-r1`·health 정상이었고 기존 서비스 시작 시각과 재시작 횟수가 같았다. 운영의 DB 설정·메모리 상한·서비스·방화벽·키·보관 정책을 변경하지 않았다.

GPS 내부는 DB1,408MiB, API640MiB, PDF묶음896MiB, 파일 정리1작업128MiB, TLS프록시64MiB로 배분한다. 구성요소 합계3,136MiB와 GPS묶음3,328MiB를 모두 제한한다. 최대치의 합과 실제 측정 사용량은 구분한다. 전용4GiB는 백신 동시 검사를 포함하지 않는다. 별도 정비시간 또는 추가 예산이 필요하다.

DB는 네이티브 PostgreSQL14.24/Timescale2.19.3, 버퍼512MB, 최대 연결64개다. 연결 예산은 단일 API28+정리2+운영2+타 프로젝트24+관리 예약3+잔여5다. 시험 역할별 상한은 GPS30/API와 정리 합계, 타 프로젝트24개다. 실제 운영 DB의 버퍼약742MiB·연결50개를 수정한 것이 아니다.

전체2CPU, 디스크 읽기/쓰기 각각8MiB/s·200IOPS를 실제 cgroup에 적용했다. DB와 API는 네이티브 systemd 서비스이고 API/PDF 바이너리는120차와 같다. 모든 보호 서비스는swap0·core0을 사용하고, 복호화 정렬·fallback·임시파일은121차의 tmpfs 경로를 사용한다. 외부포트·호스트bind가 없는 내부망이며 시험용 인증서의TLS1.2 프록시를 통과한다.

공유 부담은 **실제 다른 프로젝트나 ClamAV 실행이 아닌 모사 작업**이다. 다른 프로젝트 역할24연결·768MiB 실제 할당·SQL 및1MiB 파일쓰기/fsync를 반복하고, 별도 작업에600MiB를 실제 할당한다. 두 작업은 각각CPU25%와1,024/675MiB 상한을 갖는다. 파일 I/O는 디스크 계층에서 실행하며 임시RAM파일로 대체하지 않는다. 이를 실제 서비스들이1GiB에 수용된다는 증명이나 백신 검사 완료로 사용하지 않는다.

## 발견과 수정

- 초기 API384MiB 배분은 월간 조회 중 약95초에 OOM으로 종료되어502·응답 중단을 일으켰다. 해당 시험은 실패다. API640MiB와GPS합계3,328MiB로 재배분하고 처음부터 재시험했다. 초기 실패와 수정 후 통과 결과를 별도 보관한다.
- 파일 정리 작업이 참조 테이블 잠금에서2초 제한을 넘기면 서비스가 실패했다. `privacy_file_cleanup.process_one`은 잠금 오류SQLSTATE55P03만 트랜잭션 롤백 후 `deferred/lock_busy`로 반환한다. CLI는 같은 실행 안에서 재시도를 반복하지 않고 끝낸다. 영속 대기열은 남고 다음 작업에서 처리하며 파기 완료로 기록하지 않는다. 참조 테이블 잠금·경로 검증·실제 파일 삭제·증거 기록 순서는 유지한다. 다른 오류는 계속 실패한다.
- 최초 서비스 초기화에서 아직 로드되지 않은 unit의 `reset-failed` 오류를 무시하도록 시험 도구를 고쳤다. 운영 서비스 동작 변경이 아니다.

추가 검증도 통과했다.

- 잠금 충돌: psycopg2·psycopg3 모두 약 2초 뒤 안전하게 연기, 트랜잭션 롤백·대기열과 파일 보존, 다음 실행에서 한 번만 삭제. 권한 오류는 숨기지 않고 실패한다.
- 참조 경쟁: 미확정 참조가 있으면 연기하고, 확정된 참조가 있으면 파일을 보존한다. 마지막 참조 제거 뒤에만 삭제했다.

초기 384MiB 실패의 OOM은 부모 cgroup의 누적 수치에 남아 있다. 수정 후 각 시험의 시작·종료 차이는 0이며 원본 실패 로그도 보존했다. DB `memory.events max`는 메모리 회수도 포함하므로 OOM 횟수로 해석하지 않는다.

## 재현·인수 경계

## 다음 라운드 제안
