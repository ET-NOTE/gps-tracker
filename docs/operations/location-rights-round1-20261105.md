# 위치정보사업 준비 — 권리 요청 1차 구현

2026-11-05 · `codex/location-business-prep` · 운영 미배포.

이 라운드는 자료 범위 조회와 권리 요청 처리의 기반이다. 자동 파기, 계정 종료, 위치 수집 중지까지 완료한 버전이 아니다. 운영 DB·수집 설정·단말기 펌웨어는 변경하지 않았다. 전체 방향은 [최소 변경 정책](location-rights-minimal-change-policy.md)을 따른다.

## 확인한 결함과 수정

기존 `DELETE /auth/me`는 사용자 행을 먼저 삭제했다. 위치 기록의 외래키는 `ON DELETE SET NULL`이고 결제 주문은 `ON DELETE CASCADE`여서, 위치 기록을 남기는 동시에 보존 검토가 필요한 거래 자료를 없앨 수 있었다. 화면의 “모든 단말기 데이터 삭제”와 실제 동작도 달랐다.

새 브랜치에서는 이 API가 비밀번호 확인 뒤 409와 새 요청 경로를 반환하도록 했다. 구형 앱은 2xx 응답을 삭제 성공으로 처리하므로 202로 대체하지 않았다. 실제 파기 실행기를 갖추기 전의 개발용 차단이며, 이 차단만 운영에 배포해 탈퇴를 장기간 처리하지 않는 상태를 만들면 안 된다.

| 구현 | 동작과 제한 |
|---|---|
| 내 정보 → 개인정보 요청 | 열람·정정·삭제·탈퇴 접수, 현재 비밀번호 확인, 상태·안내 조회, 열린 요청 취소. 접수와 수집 중지·삭제 완료를 구분한다. |
| 관리자 → 개인정보 요청 | 상태 필터, 50건 단위 페이지, 요청 담당, 처리 기한, 사용자 안내, 내부 근거 번호, 변경 이력. 기한은 담당자가 적용 규정에 맞춰 지정하며 자동 법정 기한 계산은 없다. |
| 삭제 영향 조회 | 20종 자료의 수신 당시 계정 또는 명시적 소유 계정으로 조회한다. 계정당 항목별 최대 10,000건과 초과 여부를 표시한다. 읽기 전용 트랜잭션과 쿼리당 5초 제한을 사용한다. 실제 삭제 대상 전체를 확정하는 기능은 아니다. |
| 재시도·동시성 | 같은 요청 키 재전송은 같은 요청으로 반환. 종류별 열린 요청 중복을 차단한다. 관리자 처리·요청자 취소는 행 잠금과 revision으로 충돌을 거부한다. 상태와 이력은 같은 트랜잭션에 기록한다. |
| 완료 보호 | 삭제·탈퇴의 `fulfilled`는 API와 DB CHECK 양쪽에서 차단한다. 열람·정정 완료 및 처리 제한에는 사용자 안내와 내부 근거 참조가 필요하다. 근거 번호 입력만으로 실제 처리 사실을 자동 검증하는 것은 아니다. |
| 계정 경계 | 직원의 회사 선택 헤더로 본인 요청 범위를 회사 전체로 바꿀 수 없다. 삭제된 계정의 유효기간 내 access JWT도 인증 API와 새 WebSocket 연결에서 거부한다. 이미 연결된 세션의 즉시 일괄 폐기는 후속 종료 실행기에 포함한다. |
| 화면·안내 | 기존 즉시 삭제/30일 뒤 삭제/모든 데이터 삭제라는 상충 문구를 정리했다. 약관·처리방침 전체의 기간 및 법적 적합성을 확정한 것은 아니다. |

SIM 정규화, 논리 장치 ID, 하드웨어 인증키, 차량·단말기 연결 이력 및 기존 위치 외래키는 바꾸지 않았다. `0083_privacy_requests.sql`은 요청·이력 테이블만 추가한다. 요청에는 사용자 FK RESTRICT를 두어 범용 사용자 삭제로 미처리 요청이 조용히 사라지는 것을 방지한다. 실제 종료 구현 때 요청 자체의 최소 증빙·보존 근거·기간·파기도 함께 설계해야 한다.

## 자료별 처리표 초안

아래는 개발 범위 분류다. 회사가 확정하지 않은 보관 기간은 임의로 채우지 않았다.

| 자료 | 주된 경계 | 처리 방향 | 추가 확정·검증 |
|---|---|---|---|
| 계정·세션·FCM 토큰·설정 | 로그인 계정 | 종료 시 새 로그인·refresh·공유·실시간 접근 차단 후 종료 처리 | 현재 연결된 WebSocket·캐시·기기별 토큰까지 종료 검증 |
| 위치 원본·원본 JSON·이벤트·운행 통계·메모·AI 결과 | 수신 당시 계정, 관련 SIM/장치 참조 | 철회·삭제 범위의 원본과 파생본을 함께 처리. 현재 장치 소유자로 과거 이력을 재귀속하지 않음 | 목적·보관 기간, 원본/요약/캐시/최근 위치의 범위, 수집 중 동시 처리 |
| 보관 후 연결 해제한 SIM의 과거 기록 | 과거 수신 계정 | 계정별 영향 조회에 포함. 새 소유자의 기록은 제외 | 탈퇴 후 동일 SIM·동일 이메일 재가입으로 복원되지 않는지 |
| 기존 `user_id IS NULL` 위치 | 출처 미상 또는 가입 전/과거 탈퇴 등 | 별도 읽기 전용 분류. 자동으로 신규 소유자에게 넘기거나 일괄 삭제하지 않음 | 자료 생성 경위·근거·기간 |
| 차량·예약·운행·지점·방문·지출 | 회사 소유 계정, 당시 차량 배정 | 회사 소유자 종료와 직원 계정 종료를 분리 | 회사 계약·보관 근거·기간·적법한 관리자 이전 |
| 직원 명단·운전자 이름/부서 스냅샷 | 회사 소유 + 실제 정보주체 | 직원의 요청에 회사 전체 자료를 노출하지 않으면서 본인 정보 부분을 별도 처리 | 로그인 계정 없는 운전자, 대리인 확인, 타인 정보 제외 |
| 결제·포인트·SIM 충전 | 거래 주체 | 법적으로 필요한 최소 항목을 근거·만료일·접근 권한과 함께 분리한 후 나머지 처리 | 보존 법령·필드·기간, 정산/환불 중인 거래, FK CASCADE 변경 |
| 차량 첨부·렌터카 사진·영수증·내보낸 파일 | 사용자·회사·연결 행 | DB 행과 파일을 함께 추적하는 재시도 가능한 삭제 작업 | 파일 경로 목록, OCR 결과, 외부 전달본, 다운로드 링크 |
| 공유 링크·지도/리포트·알림·AI 캐시 | 계정·장치·회사 권한 | 중지 또는 종료 범위에 따라 이용·제공 차단 | 이미 발급한 링크·실시간 구독·예약된 작업 |
| 백업·배포 사본 | 원본의 동일한 처리 범위 | 실제 만료·삭제 수단과 복원 시 재공개 방지를 함께 마련 | 사본 목록·위치·기간·키·파기 증빙. 암호화 또는 복원 후 재삭제만으로 파기 완료 선언 금지 |
| 권리 요청·처리 이력 | 요청자와 처리 담당 | 최소 처리 증빙만 관리. 원본 위치·비밀번호·인증키 복사 금지 | 요청 본문도 개인정보가 될 수 있음. 접근 감사·보관 기간·파기 정책 필요 |

영향 조회에 표시되지 않는 개인정보도 존재한다. 특히 계정 기본 정보, 회사의 타인 소유 기록 안에 있는 본인 정보, 파일 내용, 기존 NULL 자료, 백업, 요청 본문 자체는 별도 조사 대상이다. 직원 계정 탈퇴가 회사 전체 삭제로 확대되지 않는다는 것과 직원 개인정보를 계속 보관할 수 있다는 것은 다른 문제다.

## 검증 기록

- 빌드 호스트의 외부 통신이 차단된 `gps-rights-test-20261105` Docker 내부 네트워크에서 가짜 계정·SIM·좌표만 사용했다. 운영 환경파일·운영 DB 복제·운영 인증키·FCM 발송은 사용하지 않았다.
- PostgreSQL 16 / TimescaleDB 2.20.3의 빈 DB에 83개 migration을 적용했다. 운영은 PostgreSQL 14 / TimescaleDB 2.19.3이므로 운영 동일 버전 및 실제 데이터 규모의 실행 계획 확인은 배포 전 조건이다.
- `ops/test_privacy_requests.py`: 비로그인/타 계정/일반 사용자 관리자 API 차단, 회사 범위 헤더 거부, 비밀번호 확인, 동시에 보낸 동일 키 4건의 단일 생성, 다른 내용 재사용 충돌, 해제된 SIM 과거 이력·새 소유자·NULL 구분, 직원/회사 분리, 기한·증빙·revision·이력, 삭제 완료 금지, 기존 DELETE의 자료 보존, 삭제 계정 JWT 거부를 검증한다.
- Rust: clippy 전체 타깃 경고 0, 단위 테스트 35개 통과·기존 외부 픽스처 의존 2개 ignored, 디버그 바이너리 빌드.
- 웹: 개인정보 요청 컴포넌트 테스트 3개를 포함한 전체 199개 통과, 프로덕션 빌드 성공. 로컬 Windows Node 22.12에서 기존 business-calendar 테스트 프로세스의 native crash가 발생해 Linux Node 22.22.2에서 전체를 다시 검증했다. 브라우저는 운영 서버 대신 실제 컴포넌트+모의 API로 모바일 390px와 PC의 접수·검토 상태 변경 및 레이아웃을 확인했다. 실제 브라우저-API 통합 검수는 아직 별도다.
- 검증 산출물: PC `%LOCALAPPDATA%/GPS-Builds/location-rights-20261105`, 빌드 호스트 `/home/etcom-hub/build/gps-location-rights-20261105`. 테스트용 DB는 tmpfs이며 검수 후 컨테이너와 네트워크를 종료·제거한다.

## 다음 라운드와 배포 조건

1. **종료·파기 실행기:** 계정 종료 상태, 재수신/조회/공유 차단, 대상을 먼저 확정한 작업 목록, 재시도·중도 실패·잔여 자료 검증, 파일 처리. 거래 보존과 회사 기록 및 요청 이력의 정책을 확정하고 실제 삭제 완료와 연결한다. 수신 당시 계정 경계와 SIM 이동을 통합 시험한다.
2. **수집·이용·제공 중지/재개:** SIM 기준 정책 버전·효력 시각, 서버의 즉시 범위별 차단, 서명된 단말기 명령·NVS·적용 ACK. 절전/망 단절 시 서버 차단과 단말기 적용 대기를 나눈다. 측위·버퍼 적재·전송을 중지하고 중지 구간 배치를 재개 후 소급 수신하지 않는다. 무위치 제어 통신은 원격 재개를 위해 별도 정의한다.
3. **권리 처리 운영:** 담당자 알림, 법정 기한 계산·기한 초과 대응, 대리인/비회원 운전자 확인, 안전한 열람 결과 전달, 사용자 답변·처리 통지, 접근 감사, 요청·증빙 보존/파기. 현재는 앱 안에서 상태를 확인하며 이메일/푸시 통지는 없다.
4. **운영 승격:** 운영 동일 DB 버전/스케일 시험, 실제 API 연결 PC·모바일 검수, 기존 APK 오류 안내, 요청부터 실제 처리까지의 담당자 운영 절차, 법무 검토된 문안, DB 백업/롤백·복원 파기 재적용을 확인한다. **요청만 접수하고 삭제·탈퇴를 끝내지 못하는 상태로 운영에 승격하지 않는다.**

기술 고도화 중 이번에 채택한 것은 멱등 요청, revision 충돌 검사, 원자적 이력 기록과 완료 보호다. 별도 암호 키 폐기 기반 삭제, 익명 경로 보존, 전면 스키마 재설계는 채택하지 않았다. 필요하면 후속 검증으로 추가하되 파기·익명화의 대체 근거로 자동 간주하지 않는다.
