# 위치정보사업 준비 · 7차: 요청 결과 조회와 개인 위치자료 제공

작업일: 2026-11-05. 분기: `codex/location-business-prep`.

## 범위

- 로그인 화면의 **개인정보 요청 결과 확인** → `/privacy/result`에서 가입 이메일·비밀번호·요청 번호로 본인 요청 하나의 안내를 조회한다. 계정 이용 종료 후에도 가능하며 일반 로그인 토큰, 위치 조회, 회사 권한을 되살리지 않는다.
- 내정보 → 개인정보 요청 → 정보 열람의 해당 요청에서 **개인 위치 기록 CSV**를 내려받는다. 현재 로그인과 비밀번호 재확인을 모두 요구한다.
- 관리자 → 개인정보 요청에서 먼저 담당자 검토 상태·처리 기한을 지정하고, 장치·기간과 본인 자료 범위를 확인해 발급한다. 발급은 요청 전체를 완료 처리하지 않는다.
- 발급은 24시간 유효하며 회수 가능하다. 재발급 시 이전 권한은 회수한다. 취소·처리 제한·계정 이용 종료·장치 파기 차단·회사 연결 범위 변경도 다운로드를 막는다.

## 자료 경계

`location_records.user_id`는 수신 당시 계정이다. 현재 `devices.owner_id`나 하드웨어 UUID를 본인 과거 기록의 소유자로 대체하지 않는다. SIM 연결을 해제한 후에도 수신 당시 본인 기록만 대상이며, 다른 계정과 NULL 소유자 자료는 포함하지 않는다. SIM/인증키/소유권을 변경하지 않는다.

자동 제공은 검토한 장치의 개인 위치 기록에 한정한다. 회사 차량 연결 이력이 있는 장치는 보수적으로 전체 제외하고 별도 검토한다. 회사 운전자 명단·업무기록·결제·첨부파일·수집이용제공 사실 확인자료 전체를 이 CSV가 대체하지 않는다. 현재 범위의 CSV가 전체 개인정보 열람 완료를 의미하지 않는다.

CSV 필드는 논리 장치 번호, 기록 시각(UTC), 위치 확정 여부, 위도·경도이다. 기록 시각은 기존 위치 기록의 시각이며 서버 도착 시각으로 단정하지 않는다. 위치 미확정 행의 좌표는 비운다. 원시 페이로드, 인증키, 계정 번호, 타인 기록, 관리자 내부 근거는 포함하지 않는다. 하드웨어 UUID 대신 기존 SIM 논리 장치 번호를 사용한다.

기존 `location_points_between` 투영을 재사용해 묶음 전송 안의 개별 위치도 펼친다. 대표 기록의 시각이 조회 구간 밖이어도 묶음 안의 구간 내 좌표는 제공한다. 동일 장치·시각·출처의 중복 처리 규칙은 기존 조회와 같다. 1만 건 제한은 펼친 좌표 기준이며 종료 시각 자체는 제외한다.

31일 길이 이하의 과거 조회 구간·장치 1~20개·1만 건 이내로 제한한다. 1만 건 초과 시 파일 생성을 거절하고 기간 분할을 안내한다. 일부만 잘라 전체 자료처럼 반환하지 않는다. 서버에 위치자료 복사본을 생성하지 않고 다운로드 시점의 남은 원본을 조회한다. 따라서 발급 후 정정·삭제로 내용이 달라질 수 있다. 다운로드된 사용자 기기의 파일은 회수할 수 없다.

## 보호 및 감사

- 공용 결과 조회는 이메일 정규화 후 계정·IP별 원자적 시도 제한, 같은 오류 응답, 비밀번호 검증을 적용한다. 결과에 내부 근거·담당자 번호·인증 토큰·위치자료는 없다.
- 결과와 다운로드는 `Cache-Control: no-store, private`, `Pragma: no-cache`, `nosniff`를 적용한다. 비밀번호는 URL·localStorage·처리 증빙에 저장하지 않는다.
- 다운로드는 요청·계정·발급·파기 제어 행과 직렬화하고 현재 상태를 재확인한다. 재발급은 요청 revision으로 충돌을 검출한다.
- `privacy_deliveries`에는 제공 범위·만료·회수 정보만 저장한다. `privacy_delivery_events`에는 발급·회수·응답 생성 시각, 담당 계정, 건수와 파일 SHA-256만 기록한다. 파일 원본은 감사 기록에 넣지 않는다.
- `download_prepared`는 서버 응답 생성 증빙이며 사용자 기기 저장 완료를 보장하지 않는다. 이 기록을 모든 수집·이용·제공사실 확인자료의 완성으로 간주하지 않는다.
- `privacy_result_limits`는 해시 키와 시도 횟수만 갖는 15분 운영 제한 버킷이다. 1일 지난 버킷은 다음 요청 시 정리한다. 법정 처리 증빙의 보관 기간을 이 값으로 정하지 않는다.

- 신규 빈 운영 시험 계정 한 개로 접수 → 이용 종료 → 결과 전용 조회를 검증했다. 일반 로그인은 409, 기존 접근·갱신 토큰은 401이며 결과 조회는 성공했다. 응답은 공개 안내 필드만 포함하고 캐시 금지 헤더가 유지됐다.
- `user@user4.com`의 계정·인증정보·SIM 연결은 동일함을 비교 확인했다. 실물 단말기·위치·거래 자료를 생성하지 않았으며 외부 메시지를 보내지 않았다.

## 열린 항목 / 다음 라운드

- 회사에 남은 직원·운전자 자료, 거래 및 첨부파일의 본인 범위 판정·마스킹·제공 수단. 계정 번호가 없는 과거 자료의 귀속을 임의로 정하지 않는다.
- 요청 번호/비밀번호 분실과 계정 인증정보를 최종 파기한 뒤의 본인 확인, 대리인 요청, 결과 통지 채널. 이 결과 화면은 비밀번호 해시가 남아 있는 현재 이용 종료 단계용이다.
- 회사 담당자가 확정할 보관 기한·거래 보존 범위·백업 및 외부 사본 파기 정책은 유지한다. 전체 삭제 완료 표시는 계속 차단한다.
- 다음 기술 라운드: **회사에 남은 정보의 권리 요청 검토·처리 증빙 연결**. 회사 권한과 정보주체의 범위를 분리하고, 자동 제공할 수 없는 항목의 사유·검토 결과·후속 처리 상태를 명확하게 관리한다.
- 기존 실외 위치/절전 검증, 최소 권한·서버 분리, TLS 운영 전환은 별도 열린 항목이다. 이번에는 펌웨어·수집 정책을 바꾸지 않는다.
