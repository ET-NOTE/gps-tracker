# HTTPS 절전·타이머 복귀 실기기 검증

2026-11-05 KST. 사용자 요청으로 자동 절전 및 타이머 기상을 짧게 설정해 실기기 반복 검증한다.
대상은 단말-520211, ESP32-C3 `68:ee:8f:21:33:64`, SIM 끝자리 47520211, 논리 장치 3163·계정 28이다.
브랜치는 `codex/location-business-prep`, 시험 펌웨어는 `https-sleep-test-0e00b7ec60`이다.

## 시험 조건

- 전용 `https-sleep-test` 프로필: 정지 창 30초, 부팅 유예 15초, GPS 미수신 유예 20초, RTC 타이머 60초.
- 시험 시작의 대기 시간에는 LTE 망 등록과 HTTPS 응답 시간이 추가된다. 정확히 전원 인가 30초 후 잠드는 설정은 아니다.
- 운영의 움직임/센서/인터럽트 검사, GPS drift 50m 기준, CPOWD 종료, 공유 전원 레일 OFF, GPIO hold, watchdog을 유지한다.
- 서버는 gps.serial.kr:443, 운영 Root X2·호스트 이름·유효기간 검증 및 HMAC v2 요청/응답 검증을 그대로 사용한다.
- 세 번의 실제 절전 진입을 RTC 메모리에 기록한다. 세 번째 복귀 뒤 추가 절전을 차단해 USB 복구·관찰을 가능하게 한다. 이 카운터는 시험 상한이며 통신 합격을 자동 판정하지 않는다.
- 서버/NVS의 원격 보고 설정은 변경하지 않는다. 시험 프로필만 유효 타이머를 60초로 사용하고 수신 설정을 NVS에 쓰지 않는다.
- 실내·USB 전원 연결 상태다. GNSS 좌표 품질·배터리 소비전류·모션에 의한 기상은 이번 시험 범위가 아니다.

## 빌드와 보호

- ESP-IDF 5.5.4로 별도 디렉터리에 빌드하고 바이너리에서 프로필, TLS 엔진, 인증 방식, 절전 활성, 타이머 60초, 3회 제한, WDT를 추출해 확인했다.
- 호스트 회귀 **190개 통과**. 기존 operating/KC/battery/상시 HTTPS 프로필 보호, 절전 중 움직임·센서·종료 실패·중단 복구, payload, 타이머, 시험 횟수 상한과 NVS 설정 보존을 포함한다.
- 대상 MAC과 패키지 해시를 확인하고 app0 `0x10000`만 업로드했다. NVS 삭제나 재페어링을 하지 않았다. HMAC 카운터 예약은 정상 부팅 과정에서 증가한다.
- 모니터는 단말기의 USB 식별자로 재연결하며 DTR/RTS=0을 유지한다. 타이머 기상 동안 사용자 조작이나 호스트 리셋 명령을 사용하지 않는다.

## 결과

**3회 자동 절전·타이머 복귀·HTTPS 수신 통과.** 사용자가 만지거나 USB를 재연결하지 않은 상태에서 수행했다.

아래 시각은 서버 수신 시각이며, 절전 이벤트는 실제 전원 차단 직전의 의도 보고다.

- 절전 보고부터 복귀 수신까지 각각 약 80.35·79.93·79.93초다. 타이머 60초와 LTE·TLS 재연결 시간이 합쳐진 값이며, 이 전체 시간을 절전 시간으로 해석하지 않는다.
- 세 복귀의 첫 보고 모두 `post_fail=0`, `brownouts=0`, `sleep_aborts=0`, `shutdown_unconfirmed=0`이다. 서버의 장치 3163·소유 계정 28에 계속 저장됐다. 첫 부팅과 세 timer wake 외의 추가 crash/reset은 관측하지 않았다.
- 1차 복귀는 USB 재열거·로그 재접속 지연으로 시리얼을 수집하지 못했다. 서버의 `wake=timer/reset=DEEPSLEEP`, 이후 `sleep_reason=timer_hb` 및 `post_ok=1`로 정상 수신과 인증된 응답 후 재절전 경로를 확인했다. 이 부분을 직접 시리얼 캡처로 확인했다고 표현하지 않는다.
- 2·3차 복귀에서 ESP32의 인증서 검증 flags=0, HTTPS 200, 요청·응답 HMAC 성공을 시리얼에서 확인했다. 관측 카운터는 602113–602114 → (서버 606210) → 610305–610306 → 614402–614403으로 증가했으며, 부팅마다 예약 블록을 건너뛰는 것은 정상이다.
- 세 번째 복귀 첫 수신 후 12:31:13.351108, 12:31:34.796090에도 정상 저장됐다. 마지막 기록은 `stay=bench_complete`로 추가 절전 차단을 확인했다. 단순 `wakes` 카운터는 이 코드에서 GPIO 기상만 세므로, timer 반복 판정에는 wake/reset 원인과 boots를 사용했다.
- 서버 원격 설정은 시험 전후 **86400초**다. 시험 중 유효 60초를 서버 설정으로 덮어쓰거나 NVS에 저장하지 않았다.
