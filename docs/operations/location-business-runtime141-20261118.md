# 141차 회사 자료 처리 요청함·증빙 검토 — 2026-11-18

## 결과와 범위

회사 소유 계정의 처리 요청함에 **상태·자료 종류 필터, 이전/다음/처음 페이지, 조회 취소**를 추가했다. 또한 증빙 저장을 취소하거나 실패했는데도 관리자가 ‘증빙을 확인했다’고 선택할 수 있던 흐름을 보완했다.

- 요청을 게시 순서로50개씩 표시한다. 상태4종과 자료6종을 조합하며 조건 변경은 첫 페이지로 돌아간다. 마지막 페이지에 실제 추가 행이 없으면 다음 버튼을 비활성화한다.
- 조회 중·실패·취소 후에는 이전 행과 제출 폼을 숨긴다. 상세는 펼칠 때 다시 확인하고, 접기/조건 변경 시 실제 HTTP요청을 취소한다. 목록 SQL에도 기존 조회 예산·중단 처리를 적용한다.
- 제출·증빙 저장 중에는 탐색과 중복 처리를 잠근다. 제출 결과가403/404/409이면 상세를 재확인해 권한이 사라진 폼을 유지하지 않는다.
- 증빙 다운로드를 시작하면 기존 확인 선택을 초기화한다. 저장 취소·실패·알 수 없는 결과·이전 리비전의 늦은 응답으로 검토 확인을 허용하지 않는다.
- 저장 완료/공유 화면 열림/브라우저 다운로드 시작은 각각 사실대로 안내한다. 이 경우에도 **실제 내용을 검토했다는 명시적 확인**을 따로 해야 한다. 공유 창을 열거나 응답을 생성했다는 사실이 전달·열람 완료를 뜻하지 않는다.
- 서버는 기존과 같이 최신 증빙ID/해시·관리자의 증빙 응답 기록·리비전·명시적 확인을 검사한다. 회사의 다운로드는 관리자의 확인을 대신하지 않는다. 보완·재제출·검토 반영은 해당 범위만 처리하며 상위 개인정보 요청을 자동 완료하지 않는다.
- 회수·만료·본인 범위 확인 해제·상위 요청 취소·계정 제한 시 회사의 접근 차단을 다시 검증했다. 이력·증빙의 자동 삭제나 보관 정책을 새로 정하지 않았다.

**구현·기능 검증 완료, 운영/dev 미배포**다. 스키마114를 유지하며 APK/펌웨어 변경·정책 활성화·추가 부하 시험은 없다. 운영 서버를 이번에 접속하거나 재점검하지 않았다. 마지막 확인 운영 상태는 API `review137-20261116-r3`, 웹 `android139-web-20261118-r1`, Android1.0.8(14)이다. 동료의 dev-gps 작업도 변경하지 않았다.
