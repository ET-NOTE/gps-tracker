## 18B 체크리스트 (구현·검증 결과)

- [x] `devices.owner_id`를 30초 후 조회해 과거 사실의 정보주체로 붙이는 구조 제거.
- [x] 계정 소유자와 실제 운전자를 구분. 귀속 불명은 임의 확정하지 않음.
- [x] 건별 시각·대상·받는 자·경로·방법·범위의 원장. 시간별 집계는 파생 조회로 분리.
- [x] 메모리 대기열·DB 장애·강제 종료의 기록 유실 방지. 기록 실패 시 제공 차단 또는 내구성 있는 사전 기록과 명확한 처리 상태.
- [x] 일반 보관기간 파기와 동의 철회 범위의 조기 파기 구분. 6개월 최소 보관 트리거만으로 정당한 철회를 차단하지 않음.
- [x] 외부 전달의 ‘시도’, ‘응답 확인’, ‘실패’를 혼동하지 않음. 공유 수신자 미상·회사 자료 한계 명시.
- [x] 전체 위치 응답 경로의 분류 목록을 역검증. 기존 RULES만 순회하는 시험으로 완전성을 주장하지 않음.
- [x] 19차 격리 환경에서 DB 소유자의 트리거 변경 권한을 일반 API에서 분리하고 DDL 거부·정당한 파기 성공 검증. 운영 적용은 별도 미완료.
- [ ] 로그 분류기 장애 감시와 기존 로그의 민감값 접근 제한·정리 정책을 점검. 이전 로그를 자동으로 지우지 않음.

## 증빙 수집 규칙

1. 실제 실행 결과와 실제 UI만 ‘운영’ 또는 ‘격리 검증’으로 표시한다. 화면에는 시각·릴리스/커밋·환경을 함께 기록한다.
2. 검증 결과를 읽기 쉽게 보여주는 보고서 화면은 **검증 보고서**로 명시한다. 관리자 설정 UI를 구현한 것으로 취급하지 않는다.
3. 자격증명·공유 토큰·실사용자 위치·회원정보는 캡처/공개 저장소에 넣지 않는다. 합성 시험값도 필요 없으면 노출하지 않는다.
4. 캡처와 원본 결과 파일의 SHA-256을 같이 보관한다. 캡처만으로 저장 암호화·접근 제한·전체 보안 요건 충족을 주장하지 않는다.
5. 19차 MFA·IP 관리·승인 화면은 구현 후 합성 자료로 실제 컴포넌트를 캡처했다. 운영 적용 캡처와 PC V3는 아직 없으며 준비 후 별도로 수집한다.

정책/실물 준비가 필요한 부분은 보류 상태를 명확히 남기되, 개발 가능한 인증·권한·기록·보관 엔진까지 모두 멈추는 근거로 쓰지 않는다.
