## 바뀐 동작

1. **접근 로그**: GPS vhost가 query·원문 요청·Referrer·User-Agent·개별 경로/공유 토큰 대신 고정 경로 분류, 허용 HTTP 메서드, 시각·접속 IP·상태·크기·지연만 기록한다. SPA 내부 rewrite로 `/other`가 될 수 있다. 이 로그는 법정 조회 취급대장이 아니다.
2. **오류 로그**: Nginx 원문에는 요청/파일명/토큰이 들어갈 수 있어, 로컬 Unix 소켓의 별도 rsyslog 프로세스가 시각·심각도·고정 오류 유형만 기록한다. 원문과 호스트명·태그도 저장하지 않는다. 호스트의 기존 rsyslog 설정/서비스는 바꾸지 않았다. `gps-nginx-log.service`는 syslog 계정, AF_UNIX, 능력 없음, 읽기 전용 파일 시스템, 자동 재시작으로 실행한다.
3. **API tracing**: 기본 TraceLayer가 URL을 넣던 span을 허용된 메서드만 담는 span으로 교체했다. 임의 메서드 문자열도 `OTHER` 처리한다.
4. **열람 자료 안내**: ‘1년이 지난 위치는 남지 않는다’는 사실과 다른 문장을 제거했다. 이미 삭제된 자료가 집계에서 빠질 수 있으며 **조회 기간과 원본 보관기간은 다르다**고 안내한다. 실제 원본 자동 파기 정책을 구현한 것은 아니다.

로그 파일: `/var/log/nginx/gps_access.log`(기존 nginx 회전 정책 14개), `/var/log/gps-nginx/errors.log`(별도 회전 14개, 파일 640·디렉터리 750). 90일 보관은 아직 적용하지 않았다. 과거 raw 로그도 임의로 지우지 않았다.

빌드는 VPS가 아닌 `etcom-hub-lan`에서 했다. 모든 시험은 합성 데이터다.

## 적용·복구

- Nginx 소스와 도구는 `ops/nginx-privacy/`. `deploy.py`가 대상 파일 해시를 검증하고 백업 후 원자적으로 쓴다. `rsyslogd -N1`, `nginx -t`를 먼저 통과해야 reload한다.
- 최초 시도는 rsyslog 검증 시 RuntimeDirectory가 아직 없어 **Nginx 적용 전에 실패**했다. 사용하지 않는 workDirectory 설정을 제거하고 재검증했다. 성공 백업은 `/home/mmm/backups/nginx-privacy-20261107-r2`; 첫 시도 기록은 같은 이름에서 `-r2`가 없는 디렉터리다.
- Nginx 원본 해시 `7a3332b2089a12c298f2c4de249840bc55469c8275b76cc35248a78b18ecd988`, 적용 해시 `6acd4e7cf0296ca4142c54f26d6bd3ec6f456c5bb27481118012b9d9ae5bf361`.
- API는 고정된 소스/바이너리/검증 manifest로 `release_api.py check` 후 `apply`. 스키마·웹·환경설정·처리기는 변경하지 않는다. 실패 시 이전 바이너리를 복구한다.
- API 복구가 필요하면 **현재 해시·스키마·설정이 그대로인지 확인한 뒤**, 해당 artifact의 `sudo python3 release_api.py rollback`. 17차 API로만 돌아간다. 17차 이전 스키마/바이너리로 되돌리는 스크립트가 아니다. 복구하면 tracing·안내 수정도 이전으로 돌아가므로 후속 수정이 필요하다.
- Nginx 복구는 `/home/mmm/gps-artifacts/nginx-privacy-20261107/deploy.py rollback`. 성공 백업 `nginx-privacy-20261107-r2`가 코드에 고정되어 있고 현재 파일 해시를 확인한다. 복구하면 기존 raw 로그 문제가 재발하므로 긴급 복구 후 재수정한다. 기존 파일·로그를 수동 삭제하지 않는다.
