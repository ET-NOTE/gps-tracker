# 위치정보 권리 처리 5차 — 계정 이용 종료와 대상 자료 처리

2026-11-05. GPS 운영 서비스에 개인정보 요청 화면, 관리자 계정 종료 처리, 로그인·수집 제한 및 범위를 한정한 자료 처리 작업을 연결했다. 이 라운드는 **계정 이용 종료와 확인 가능한 개인 자료 처리**를 구현한다. 모든 개인정보·백업의 파기나 사업 준비 전체의 완료를 의미하지 않는다.

## 적용 범위

- 운영: `gps.serial.kr`, release `account-closure-20261105-r1`, schema **87**.
- 브랜치: `codex/location-business-prep`. 이전 운영 API/웹 소스에 관련 변경만 합쳐 배포했다. 별도 법인 화면 수정 등 무관한 브랜치 변경은 제외했다.
- dev GPS와 Shield의 바이너리·웹 경로·프로세스는 변경하지 않았다. 이번 라운드의 펌웨어 및 APK 변경은 없다.
- 실제 `user@user4.com`은 종료하지 않았다. 계정·비밀번호·SIM 소유권의 변경 없음과 기존 로그인 세션의 개인정보 요청 화면 접근을 확인했다.

## 처리 흐름

1. **내정보 → 계정 → 개인정보·회원 탈퇴 요청**, 또는 **개인정보 요청** 탭에서 요청을 접수한다. 현재 비밀번호를 검증하고 요청 키로 중복 접수를 방지한다. 접수만으로 수집 중지나 탈퇴 처리가 실행되지는 않는다.
2. 관리자는 **개인정보 요청**에서 본인/대리인, 대상 자료·회사 관계·처리 기한을 검토한다. 검토 확인 후 **계정 이용 종료**를 시작한다. 본인 관리자 계정의 자체 종료 실행은 거부한다.
3. 하나의 DB 트랜잭션에서 계정을 제한하고 로그인 갱신 토큰·FCM 수신 토큰·공유 링크·회사 초대를 철회한다. 직원 로그인 연결을 해제하고 렌터카 인수 링크는 무효화한다. 인수 사진이 참조하는 링크 행은 삭제하지 않는다.
4. 계정 처리 워커가 수신 당시 본인 계정 기준으로 대상 자료를 처리한다. 회사·거래·직원 관계가 있는 계정은 자동 삭제를 보류한다. 실패는 롤백하고 재시도하며 변경 없는 재실행은 처리 이력을 중복 생성하지 않는다.
5. 대상 개인 자료와 로컬 첨부 정리가 확인되더라도 계정·감사 자료, 회사·거래 자료 및 백업·외부 사본 검토가 남으면 **검토 중**으로 유지한다. 관리자 수동 상태 변경으로 전체 삭제 완료를 우회할 수 없다.

## 차단 경계와 SIM 정책

| 경로 | 적용한 동작 |
|---|---|
| 로그인 | 올바른 비밀번호라도 종료 계정에는 토큰을 발급하지 않고 이용 종료 및 요청 번호를 안내한다. 틀린 비밀번호는 일반 인증 실패로 처리한다. |
| 기존 세션·파일·직원 위임 | 매 요청에서 본인 계정과 위임 회사 계정의 제한 상태를 확인한다. 이전 access/refresh 토큰을 거부한다. |
| 실시간 연결 | 접속·구독·명령 및 이벤트 전송에서 제한 상태를 확인한다. 유휴 연결은 30초 확인 주기로 닫는다. 이미 진행 중인 이벤트·FCM 전송은 계정 잠금으로 종료 트랜잭션과 직렬화한다. |
| 단말기 수집 | 기존 하드웨어 서명 검증을 유지한다. 종료 계정 소유 SIM에는 서명된 `stored=false`, `privacy_blocked=true` 응답을 주며 위치를 저장하지 않는다. |
| 늦은 작업·재전송 | 위치·이벤트·개인 자료 및 최근 위치 캐시의 DB 쓰기에서 계정/SIM 제한을 다시 확인한다. 종료 전에 시작한 작업도 차단 후 자료를 재생성할 수 없다. |
| 예약·알림 배치 | 종료 계정을 대상에서 제외한다. 해당 계정의 보류 자료 때문에 다른 계정의 배치가 계속 실패하지 않도록 한다. |

SIM 기준 논리 장치와 하드웨어 인증키는 유지한다. 계정 종료 시 SIM 소유권을 NULL로 만들거나 다른 계정에 자동 연결하지 않는다. 같은 이메일의 재가입, SIM 재사용·관리자 이전은 아직 별도의 처리 범위 검토가 필요하다. **현재 종료된 이메일로 즉시 재가입하는 기능은 제공하지 않는다.**

서버에서 저장하지 않는 것과 단말기의 측위·버퍼·송신 중지는 다르다. 이번 라운드에서 단말기의 물리적인 측위 중지를 완료한 것으로 표시하지 않는다. 이미 인증 검사를 통과해 응답 중인 일반 REST 요청은 종료 트랜잭션과 완전히 직렬화하지 않으며, 새 요청은 거부한다.

## 자동 처리 범위와 보류

자동 처리 대상은 워커의 고정 목록에 있는 본인 `user_id`/`owner_id` 자료다: 원본 위치, 이벤트, 일 통계, 운행 메모, AI 결과·요청·사용 기록, 개인 지오펜스, 장치 명령·서류, 통신 알림 에피소드. 연결 해제한 과거 SIM의 본인 기록도 포함한다. 최근 위치·차량 사진 캐시를 비우되 논리 장치·인증키·SIM 식별자는 남긴다.

- 현재 SIM의 다른 계정 기록과 `user_id IS NULL` 기록은 자동 삭제하지 않는다.
- 이전 SIM 단위 집계는 계정 경계를 입증할 수 없어 별도 검토로 남긴다.
- 회사 소유 자료 또는 직원 연결이 있으면 개인 처리 실행을 보류한다. 직원의 로그인 연결 해제만으로 회사의 운전자 이름·위치 스냅샷이 익명화됐다고 판단하지 않는다.
- 계약·사진·영수증·결제·포인트·USIM 거래 자료는 별도 검토 대상이다. 이 보류 상태가 무기한 보관의 근거는 아니다.
- 개인 서류·차량 사진은 기존 파일 정리 대장에 연결한다. 공유 참조·미처리 파일이 남으면 개인 범위 검증도 완료하지 않는다.
- 계정 프로필·감사 이력, 백업·외부 사본, SIM 재사용은 명시적인 보류 사유다. `external_copies_verified=false`, 요청 `in_review`, 작업 `review_required`를 유지한다.
- 계정 행을 먼저 삭제하지 않아 기존 SET NULL/CASCADE가 귀속 정보나 거래 자료를 유실시키지 않는다.

## 운영 실증

실제 자료가 없는 신규 검증 계정 **34**, 요청 **1**을 생성해 다음을 확인했다. OTP/SMS/메일·FCM 발송 및 결제는 실행하지 않았고, 실제 장치나 위치도 만들지 않았다.

- 정상 로그인 → 현재 비밀번호를 확인한 탈퇴 요청 → 관리자 처리 시작 성공.
- 이전 access/refresh 토큰은 401, 종료 계정의 올바른 비밀번호 로그인은 409와 요청 번호 안내.
- 대상 개인 자료 검증은 성공했으나 백업·계정 자료 검토는 남아 있으며 전체 완료로 표시하지 않음.
- `user@user4.com`의 계정·비밀번호·SIM 소유권은 그대로 유지됨.
- 검증용 임시 비밀번호 파일은 PC와 VPS에서 제거함. 검증 계정은 제한 상태로 남아 있으며 사용자 행 전체를 삭제한 것은 아님.
- 기존 user4 브라우저 세션에서 PC와 390px 모바일의 요청 화면·입력창·자료 범위 조회를 확인했다. 실제 요청 제출이나 계정 종료는 하지 않았다. 모바일 문서 폭과 입력창은 화면을 넘지 않았다.
