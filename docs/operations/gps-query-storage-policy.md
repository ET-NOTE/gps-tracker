# GPS 조회량 및 저장 공간 운영 기준

2026-10-31, 13차 기준. GPS 운영 서버에 적용하는 기준이며 dev-gps·Shield와 다른 DB의 삭제나 정책 변경을 포함하지 않는다.

## 위치 조회

| 경로 | 범위·응답 기준 | 초과·실패 처리 |
| --- | --- | --- |
| 좌표 페이지 API | 최대 31일, 요청당 기본 2,000 / 최대 5,000점. 종료 시각 제외 | 잘못된 범위와 다른 계정/조건의 커서 거절 |
| 웹 원본 이력 | 커서를 끝까지 순차 조회, 최대 250,000점 | 부분 이력을 완료로 표시하지 않고 요약 조회 안내 |
| 웹 1분 요약 | 최대 31일 | 네트워크 요청 전에 5분·1시간 요약 안내 |
| 웹 5분·1시간 요약 | 최대 366일, 요청당 2,000구간, 전체 최대 120,000행 | 중복·역순·범위 밖·비정상 응답과 중도 실패 시 부분 결과 폐기 |
| 요약 API | 요청당 최대 4,999구간 길이, 경계 포함 시 최대 5,000구간 | 더 짧은 범위로 요청하도록 거절 |
| 구형 이력 API | 기존 전송 묶음 수 limit 의미와 포함 경계 유지 | 신규 UI는 커서 API 사용. 묶음 수를 좌표 수로 오인하지 않음 |

서버가 확정한 SIM 논리 ID·수신 당시 소유자·같은 시각의 소스 구분·배치 내부 시각을 유지한다. 페이지 경계의 속도는 앞선 65초 문맥을 사용하므로 페이지 분할로 달라지지 않는다. 원본 JSON이 필요한 다른 API는 기존 함수를 사용하고, 위치 화면용 조회는 필요한 스칼라 필드만 읽는다. 데이터의 시간·속도·위치·배터리 값을 새로 보정하지 않는다.

운영 측정은 동일 과거 날짜의 행 수와 전체 응답 SHA256을 먼저 비교한 뒤 지연을 비교한다. 공유 VPS의 캐시·동시 부하 영향이 있으므로 세 번의 중앙값도 고정 성능 보장으로 취급하지 않는다.

## 용량 점검

`ops/audit_gps_storage.py`는 파일·DB를 읽어 JSON을 출력한다. 삭제·회전·압축·예약 실행 기능은 없다. 충분한 읽기 권한으로 운영 env 경로를 인자로 전달하고, 결과는 공개 웹 경로가 아닌 운영 증빙 폴더에 보관한다. 자격 증명·사용자 정보·좌표는 출력하지 않는다.

- 일반 사용자 가용 공간 5GiB 미만: 경고, 배포 증가량·DB/WAL·로그 추세 확인.
- 2GiB 미만: 긴급 검토, 백업과 배포 전 공간 확보 또는 볼륨 증설.
- 기존 배포 차단선 1GiB 유지. root 예약 공간을 가용 공간으로 계산하지 않는다.
- 최초 수치만으로 남은 일수를 추정하지 않는다. 반복 점검 결과를 시간순으로 비교한다.
- 현재 웹과 명시된 직전 복귀 웹은 항상 보호한다. 다른 서비스·업로드·사용자 자료·DB/WAL·백업을 빌드 캐시로 취급하지 않는다.

최초 점검: VPS 가용 4,395,560,960바이트, GPS 운영 DB 111,928,099바이트. GPS 공용 releases 2,033,999,872 / gps-artifacts 2,379,116,544 / backups 1,058,258,944바이트. 이 디렉터리에는 과거 dev 작업도 섞여 있어 폴더 단위 일괄 삭제할 수 없다. PostgreSQL 전체 7,946,137,600바이트 중 다른 DB `bbb_db`가 5,909,144,355바이트이며 GPS 운영 자료가 아니다. 공유 시스템 journal 1,837,350,912바이트도 이 작업에서 변경하지 않았다.

## 데이터·백업 보관

현재 GPS 위치 자료에는 7일 경과 후 압축 정책이 있고 자동 삭제 정책은 없다. 압축은 원본 보존이며 보관 기한을 의미하지 않는다. 운영 기록의 자동 삭제는 계속 비활성 상태다.

현재 배포별 DB dump는 22개이며 최신 dump에 오프호스트 검증 영수증이 없는 상태로 발견했다. 영수증 부재가 복사본 부재를 확정하지는 않는다. 배포 시 백업과 별개로 정기 백업의 시간표·외부 보관 위치·복구 시험 주기는 운영 결정이 필요하다. 이번 라운드에서 확인된 system timer에는 GPS 전용 정기 백업이 없었다.

추후 자동 보관을 도입할 때의 제안 기준:

1. 일간 7개·주간 4개·월간 3개를 서로 다른 호스트에 보관하고, 업로드·설정 등 DB 밖 복구 자료도 포함한다.
2. 삭제 전에 SHA256 일치와 최근 복구 시험 증빙을 요구한다. 목록을 읽을 수 있다는 것만으로 복구 성공으로 판정하지 않는다.
3. 현재/직전 배포본·장애 조사용 백업·현재 인증 마이그레이션 복귀 자료는 개수/기간과 관계없이 보호한다.
4. 이전 배포의 웹 자산은 구버전 앱 캐시가 참조할 수 있으므로 실행 중인 버전·APK 다운로드·연결된 경로를 확인한 후 정리 대상을 확정한다.
5. 데이터·백업 삭제 자동화는 별도 승인 후 도입한다. 이 문서와 점검 도구는 삭제를 활성화하지 않는다.

남은 운영 결정: 정기 백업의 외부 저장 위치·스케줄, 복구 시험 주기, 가용 공간 증설 또는 검증된 과거 산출물 정리. 성능 작업 완료와 이 결정을 구분해서 보고한다.
