`location_points_between` 결과를 재사용하는 SQL 실행 경계를 명시하여 동일 좌표의 반복 복호화를 줄였다. 좌표 유효성, 시간 범위, 소유자, 동일 시각의 source 우선순위는 유지했다. 법인 지도와 정보주체별 거리 집계에도 같은 처리를 적용했다.

리포트·CSV·XLSX·법인 지도·거리 집계의 위치 SQL이 일반 이력 조회와 **프로세스당 동시2개 제한,250ms 대기,SQL20초 제한,연결 종료 시 DB 취소**를 공유한다. 다운로드와 법인 GET의 혼잡 응답에도114차의 최대2회 자동 재시도를 연결했다. 계정·회사 변경 뒤에는 이전 요청을 재전송하지 않는다. 쓰기·다른 다운로드·일반 네트워크 오류는 이 재시도 대상이 아니다.

SIM 귀속·차량 배정·동의·철회·이용 중지·기록 보관 정책·암호화 형식은 변경하지 않았다. 새로운 영속 평문 캐시를 만들지 않는다. 다만 복호화된 SQL 중간 결과는 메모리 또는 임시 파일에 놓일 수 있다. DB 정렬/중간 결과의 임시 파일과swap 보호는 기존 열린 항목이다.

## 지속 부하

제한 응답429와 최종 조회200을 구분하며, 자동 재시도 후에도429가 남으면 성공으로 집계하지 않는다. 수집 성공은 HTTP 응답뿐 아니라 저장된 원본 행 수로 대조한다. 지정 시간 뒤 진행 중인 요청을 회수하므로 실제 종료 시각은 약간 늦다. 재시도는 웹과 같은 최대3회·Retry-After·jitter를 적용한 시험 클라이언트이며 실제 브라우저 부하 시험은 아니다.
