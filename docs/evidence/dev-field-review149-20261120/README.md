## 화면 수치의 해석과 병합 주의점

지점 방문 화면은 첫 내부 위치, 마지막 내부 위치, 첫 외부 위치를 따로 표시한다. 화면의 체류 확인 구간은 마지막 내부 시각에서 첫 내부 시각을 뺀 값이다. 현장 통과 시각과 비교할 때 GPS 수신 간격을 함께 기록하면 차이를 설명할 수 있다. 관련 소스는 dev 커밋의 `routes/fleet_sites.rs` 및 `components/business/FleetSites.jsx`다.

운행 화면의 ‘확정 주행거리’는 포함 대상 운행의 `distance_m`를 합산한다. 국세청 엑셀의 ⑦주행거리는 유효한 전·후 계기판 값이 있으면 그 차이를 우선하고, 없으면 운행기록 거리로 대체한다. 두 기준이 다른 차량은 같은 운행 건을 선택해도 거리 합계가 다를 수 있다. 검수표에 확정 건수·운행기록 거리·계기판 차이·엑셀 합계를 구분해 기재한다. 코드 근거는 dev의 `CorporatePanel.jsx`의 `dailyDistance`와 `services/xlsx_report.rs`의 `nts_row_distance`다.

dev의 XLSX 저장 코드는 `CorporatePanel.jsx` 1660행에서 브라우저 Blob URL을 만들고 링크 다운로드를 실행한다. 운영 148차는 같은 지점에서 Android 저장·공유를 처리하는 `saveBlob`을 호출한다. dev 코드 흡수 시 운영의 저장·취소 처리를 보존해야 한다. 이번에는 Android 실물 저장을 다시 실행하지 않았다.

개발 배포 소스의 지점, 국세청 보고서·인쇄, 법인차 보고서, 서비스 진입 관련 웹 검사 52개를 Linux 빌드 환경에서 실행해 모두 통과했다. 초기 Windows 실행에서는 한 테스트 파일의 Node 프로세스가 비정상 종료되어 동일 소스로 Linux에서 재검사했다. 현장 자료, 실전화번호, 원본 위치, 인증 토큰은 검토 기록에서 제외했다. [52개 검사 출력](web-tests.tap)
